## 协议及运行变化

- 配置默认 `allowStaleDuringReindex=false`、`historicalEvidenceEnabled=false`；开启历史需填写正数 `historyRetentionDays`。保留期限目前约束能否读取，不代表按期释放磁盘空间。
- 新增迁移 V58、V59、V62、V63；版本号需合并前复核是否冲突。它们在本地尚未应用到真实数据库。
- 每个知识问答最多增加分类、生成、Judge 三个聊天模型调用；需要服务端与 model-service 同步升级以支持 `TRUSTED_JSON`，延迟/费用尚未真实测量。
- 缺少不可变源标记的旧索引不能自动取得可信身份，需要重新解析/重建。旧会话中没有服务端 answerId 的 assistant 正文保留在数据库，但 API 隐藏并提示重新提问。
- Workflow 最终回答重新在请求授权的知识库范围内检索。没有知识库范围时明确失败，不将工具返回文本直接标为可信依据；对依赖通用工具自由总结的流程属于行为变化。
- assistant 手工追加必须引用本用户服务端 answerId，客户端提供的正文/引用不能赋予可信状态。
- AGENT_TASK Webhook 仅含任务标识/状态/answerId；旧排队事件也不发送缓存答案正文。新增 `GET /api/v1/{agent|assistant}/sessions/{sessionId}/queries/{messageId}`（兼容 `/api/open` 前缀）读取结果，逐个复核原任务的全部 Space 与原 Agent 能力。幂等 POST 同样检查原任务范围，不能用缩小请求范围绕过；GET 返回 no-store。契约见 `docs/openapi-v1.yaml`。
- 新生成的知识回答不再提取为缺乏证据沿袭的长期记忆；历史摘要和旧模型消息不作为新回答证据。
