# Problems 收集箱

此页只用于快速记录新发现、尚未分析和尚未分类的问题。它不是待完成任务总览，也不保存已经完成的问题历史。

## 使用规则

每条问题至少记录：

- 发现时间与环境；
- 用户可见现象；
- 最小复现步骤；
- 预期结果与实际结果；
- 日志、请求 ID、任务 ID、文档 ID 或截图位置；
- 初步影响范围，但不要在证据不足时直接写根因。

完成分析后：

- 需要编码的工作移动到“待完成任务”；
- 已开发只差验证的工作移动到“待验收任务”；
- 已开始处理的工作移动到“进行中任务”；
- 已修复并验证的工作移动到“已完成任务”；
- 具体设计与解决方案写入对应功能文档，不在本页长期堆积。

## 未分类问题

### E2E Smoke 未清理临时用户和默认个人空间

- 发现时间：2026-07-16。
- 环境与版本：Win10 本机 Docker Compose，`frontend-ui-ux` 工作分支。
- 现象：`scripts/e2e-smoke.ps1` 会注册随机测试用户，结束时删除普通测试文件、测试 Space 和本地临时目录，但没有删除测试用户及注册时自动创建的个人空间。
- 复现步骤：执行一次 `e2e-smoke.ps1`，等待脚本成功并进入 `finally` 清理，再查询用户和 Space 数据。
- 预期：一次性 E2E 在成功或失败后清理全部测试业务数据，或明确复用一个受控测试账户。
- 实际：本次运行留下用户 ID 41 和默认个人空间 ID 46；临时测试 Space ID 47 已清理。
- 证据：脚本 `finally` 仅调用普通文件和测试 Space 删除接口，未调用用户删除能力；当前 `UserController` 未发现账户删除接口。
- 影响：重复执行会持续累积无用用户和个人空间，污染验收环境并增加后续数据清理风险。
- 初步判断：需要先确定“受控固定测试账号”或“管理员级级联清理接口”的治理方案，再分类进入脚本或账户生命周期功能文档。
