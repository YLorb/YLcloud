# 项目架构总览

YLcloud 采用“模块化单体业务核心 + 独立基础能力服务”的架构。Spring Boot 持有业务规则和事务边界，模型与解析被视为可替换外部能力，MySQL、MinIO、Qdrant 分别承担事务事实、二进制对象和向量索引。

## 关键架构判断

1. 文件不是孤立对象。一个物理内容可被个人文件树、Space 文件、版本记录和 RAG 文档引用。
2. RAG 是文件生命周期的派生索引，不是文件系统本身；索引丢失可以重建，原始文件与业务引用不能依赖向量库恢复。
3. 知识画像是基础 RAG 成功后的可选增强模块，拥有独立任务、状态和失败语义。
4. 外部存储不参与 MySQL 本地事务，因此系统使用“先隔离、后提交、再对账”的 Saga/补偿思想，而不是伪装成分布式 ACID。
5. 异步任务的正确性依赖数据库状态和 CAS，不依赖某个 Java 线程一定存活。
6. 个人网盘与 Space 复用文件树体验而不合并领域模型：`user_file` 负责个人所有权，`space_file` 负责协作与默认知识化，两者共享 `file_info` 和物理对象时不复制字节。
7. Space 是当前知识与授权边界。文件展示、知识库范围、检索、问答和引用必须基于同一授权上下文；文件级 ACL 作为后续扩展，不属于当前已交付能力。

## 架构质量属性

| 属性 | 当前机制 |
|---|---|
| 正确性 | 状态机、事务、唯一约束、摘要校验、精确 point count |
| 可恢复 | 持久任务、租约、超时回收、启动/定时对账、补偿 |
| 安全 | JWT、Space 角色、资源级校验、文件型 Secret |
| 可追溯 | 查询日志、配置日志、流水线事件、审计日志、版本 |
| 可扩展 | Parser/Model 接口、检索路由、独立功能模块 |
| 可部署 | Compose 健康依赖、Flyway、持久卷、环境覆盖 |
