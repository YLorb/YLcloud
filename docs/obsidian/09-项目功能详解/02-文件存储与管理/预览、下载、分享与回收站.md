# 预览、下载、分享与回收站

## 产品目标

用户可以在授权范围内预览或下载文件，也可以通过分享码给未登录访客开放指定文件。误删先进入可恢复回收站，只有彻底删除才减少逻辑引用。

## 访问路径

FileController 提供个人文件 preview、stream、download；SpaceFileController 提供 Space 文件对应能力；ShareController 通过 shareCode 提供匿名 preview/download/stream。三条路径最终都访问 MinIO，但授权来源不同，不能只复用 URL 而跳过资源校验。

## 预览与下载

- 预览根据类型返回可内联内容或短期预签名 URL。
- stream 支持浏览器直接读取，需正确处理 Content-Type、Content-Disposition 和范围请求能力。
- download 使用附件语义并保留安全文件名。
- RAG citation 中的 previewUrl/downloadUrl 仍需在访问时校验 Space 权限。

## 分享

file_share 保存分享码、目标节点、状态和可选时效。ShareCodeUtil 生成不可预测代码。公开入口只允许访问分享绑定的对象，不能通过修改 fileId 横向访问。

## 回收站

逻辑删除将 user_file 标记为回收站状态，目录列表默认排除；restore 检查父目录、名称冲突和引用有效性后恢复。purge 才删除逻辑引用，并在最后引用归零时触发物理清理。

~~~mermaid
stateDiagram-v2
  ACTIVE --> RECYCLED: delete
  RECYCLED --> ACTIVE: restore
  RECYCLED --> PURGED: purge
  PURGED --> CLEANUP: 最后引用归零
~~~

## 设计原因

回收站与 MinIO 版本控制解决不同问题：前者恢复用户的逻辑节点，后者保留对象版本用于文件版本和安全删除。把“移入回收站”直接映射成 MinIO delete 会破坏恢复和共享引用。

## 失败与安全

- 无身份 401、无权限 403、不存在或不可暴露 404、名称冲突 409。
- 文件名必须进行响应头安全编码，防止 header injection。
- 分享失效、资源被彻底删除或引用归零后，旧分享不能继续访问。
