# mq-v5：知识流水线任务迁移

## 目标

将 Knowledge Pipeline 的解析、切块、派生和恢复迁入 knowledge 队列，同时保留旧领域任务只读展示和回滚兼容。

## 依赖与输入

- TASK-20260725-019 已通过观察。
- TASK-20260725-004/005 已定义文件/知识生命周期和 `ACTIVE/NEEDS_REVIEW` 质量状态；Pipeline 任务只驱动这些状态，不创建平行状态机。
- `KnowledgePipelineExecutorService`、Pipeline Service/Recovery/Event 及现有任务表。

## 修改范围与产物

- 为 Pipeline 阶段定义任务类型、依赖关系和稳定 `task_key`。
- 领域记录增加 `async_task_id`；新任务写统一表，旧记录不回填。
- 拆出同步执行核心，Consumer 负责异常传播和结果事务；移除新路径的 `@Async`。
- 使用知识资产/文件版本作为资源栅栏，旧解析结果不得覆盖新文件。
- 大文件阶段拆成有界任务，不在一个 Rabbit delivery 内串行执行无限批次。
- 统一 Pipeline 状态与任务状态映射；旧任务详情提示无 attempts。
- knowledge 默认并发 2、prefetch 1。

## 不包含

- 改变解析器选型、切块算法和知识产品状态定义。
- RAG 消费和 Qdrant Point ID 切换。

## 验收标准

1. 新 Pipeline 任务全部关联统一任务，旧记录仍可列表/详情读取。
2. 解析器崩溃、模型/Qdrant 暂停、租约过期均按统一重试处理。
3. 旧文件版本完成时为 `SKIPPED_STALE`，不发布新版本知识资产。
4. 手工重试复用 taskId，下一次领取版本递增且审计完整。
5. Flag 回切后旧 executor 仅处理旧路径记录。

## 测试与通过

- 覆盖多阶段成功、阶段失败、进程退出、重复事件、文件替换/删除、取消和兼容列表。
- 验证吞吐、单任务时长、Rabbit consumer timeout 和 backpressure。
- 满足 TEST-20260725-002 通用门禁和 `mq-v5` 场景。

## 风险与回滚

- Pipeline 状态和统一状态可能漂移：所有跨表状态更新放在同一 MySQL 事务，并加定时只读审计。
- 回滚关闭 `async.mq.knowledge`，保留新增关联和任务历史。
