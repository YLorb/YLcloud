# 用户组与用户页面

## 目标与需求覆盖

完成 `/admin/user-groups` 与 `/admin/user-list` 的前端管理原型，复用现有权限模型概念但不接真实账号和授权 API。

## 前置依赖与输入

- 前置：TASK-20260913-001。
- 输入：现有 AccessManagementPanel、AdminUser/PermissionGroup 类型、用户组配额与统一授权文档。
- 下游测试：[[10-规划与实施/测试/TEST-20260913-001-管理后台前端页面验收要求]]。

## 修改范围与预期产物

1. 用户组页提供搜索、分页、权限/配额摘要、创建/编辑、权限矩阵、配额表单和删除确认。
2. 用户页提供用户名/昵称/邮箱搜索、角色/状态/组筛选、分页、创建/编辑、状态变更、归组和单用户权限覆盖详情。
3. 系统组、当前账号、默认组等受保护对象在 UI 上禁用危险操作并解释原因。
4. 表单包含必填、长度、邮箱、密码演示、配额范围和冲突校验；不使用真实个人数据。

## 明确不包含

- 创建真实用户、修改密码/角色/状态、写入组权限或配额、实现新的授权规则。

## 验收标准

- 两页不再只有空表头，具备可注入数据的完整 CRUD 原型和结构化空状态。
- 用户与用户组职责分离，入口不再把全部权限管理塞入参数设置页。
- 受保护对象的禁用态、危险确认和模拟操作提示一致。

## 测试、风险与回滚

- 测试：搜索/筛选/分页、表单校验、权限三态、系统组/当前账号保护、删除冲突、失败不改数据和敏感字段检查。
- 风险：前端保护可能被误认为安全边界；页面说明必须强调最终权限由后端判定。
- 回滚：恢复静态 Users/UserGroups 页面；保留 AccessManagementPanel 与真实 API。
- 实现 Agent/LLM 必须生成完整测试用例和独立测试记录，并回写状态与证据。
