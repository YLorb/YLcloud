## 文档职责

| 部分 | 回答的问题 |
|---|---|
| 项目简介、概览、目标 | 这是一个什么项目，服务谁，边界和成功标准是什么 |
| 任务状态 | 已完成、正在做、尚未做、已实现待验证分别有哪些 |
| 项目架构 | 系统如何分层、部署、存储、保持一致并恢复故障 |
| 状态机设计 | 长流程为什么不能只用布尔值，代码中的状态如何流转 |
| 功能总览 | 用户和开发者从哪里进入每个功能 |
| 功能详解 | 每项能力的产品动机、原理、流程、核心类、接口、表和权衡 |
| problems.md | 只接收尚未分析归类的新问题，不作为正式待办 |

## 维护原则

- 链接方向固定为：总导航 → 分区总览 → 细分文档。
- 细分文档不添加“返回总览”链接，不与上级页面互链。
- 同一事实只在一个权威页面维护；其他页面需要引用时只从上游指向权威页面。
- 任务状态必须有代码、迁移、测试或运行证据；“已开发”与“已验收”分开。
- 标签使用小写英文；RAG 子主题必须同时带 rag 标签，例如 embedding 文档同时带 rag、embedding。
