# 管理后台共享骨架与 Mock 数据层

## 目标与需求覆盖

建立全部管理页面共用的展示骨架、状态规范和可替换数据边界，覆盖 REQ-20260913-001 的统一结构、默认空数据、临时操作和演示提示要求。

## 前置依赖与输入

- 无实施任务前置。
- 输入：ADR-20260913-001、现有 `ManagementPage`、`Dialog`、`PageState`、`StatusBadge`、`Tabs`、`data-table` 和主题 Token。
- 下游测试：[[10-规划与实施/测试/TEST-20260913-001-管理后台前端页面验收要求]]。

## 修改范围与预期产物

1. 定义 `AdminDataSource`、分页/排序/筛选 Query、查询结果、命令结果和 `mock/api` 来源标识。
2. 实现默认空数据、可注入 fixture/错误、确定性内存命令的 `MockAdminDataSource`。
3. 建立 DataSource Context 和页面级查询/命令状态辅助函数。
4. 新增或扩展页面标题、演示提示、筛选栏、数据表、空状态、分页、详情面板、表单弹窗和确认弹窗。
5. 统一“演示数据已更新，未保存到服务器”等提示，禁止各页面自行省略演示标识。

## 明确不包含

- 14 个领域页面的业务字段和布局。
- 真实 API 适配器、后端改动、本地持久化和新依赖。

## 验收标准

- 共享组件可分别渲染 loading、ready-empty、ready-data、error 和 submitting 状态。
- Mock 默认无数据、无网络请求、无随机性；fixture 和失败可由测试显式注入。
- 临时命令只修改当前 Provider 生命周期内的数据，刷新后重置。
- 危险命令必须经过确认，重复提交被阻止，失败不修改数据。
- 组件具有语义化标签、可见焦点、焦点恢复和演示模式提示。

## 测试、风险与回滚

- 测试：类型/查询工具单元测试、共享组件测试、Mock CRUD/失败/重置测试、键盘与焦点测试、无网络请求断言。
- 风险：公共组件抽象过度或不足；以现有页面需求为边界，不构建通用低代码框架。
- 回滚：删除新增 Provider/组件并恢复页面直接使用现有组件；不得删除现有真实 API。
- 实现 Agent/LLM 必须生成完整测试用例和独立测试记录，回写状态与证据；未通过必选测试只能标记 `pending-verification`。
