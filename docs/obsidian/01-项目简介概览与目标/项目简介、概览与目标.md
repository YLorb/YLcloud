# 项目简介、概览与目标

## 一句话定义

YLcloud 是一个把“个人网盘、团队知识空间、RAG 知识库和知识画像”整合到同一文件生命周期中的全栈系统。文件只需上传或导入一次，系统就能完成存储、协作、索引、检索问答与可选知识增强，同时保持 MySQL、MinIO 和 Qdrant 之间可追踪、可补偿的一致性。

## 项目面向的用户

- 个人用户：上传、整理、预览、下载、分享和恢复文件。
- 团队成员：在 Space 中协作管理文件，并按 OWNER、ADMIN、MEMBER 控制权限。
- 知识库使用者：从一个或多个已授权 Space 中检索、问答并查看引用来源。
- 知识运营者：查看文档画像、分类、标签、质量问题、版本差异和审核记录。
- 平台管理员：管理站点设置、模型端点、Secret 引用和部署状态。

## 产品边界

YLcloud 当前是一套可部署的单体业务后端加独立模型、解析和存储服务。它不是通用对象存储实现，也不是模型训练平台。它负责把外部能力编排成可靠的业务闭环：

1. MySQL 保存业务事实、权限、任务、状态和补偿记录。
2. MinIO 保存原始文件、分片和版本化对象。
3. Qdrant 保存可检索的向量点。
4. model-service 提供 embedding、rerank 和生成能力。
5. document-parser-service 提供版面、OCR、页面和结构化解析能力。
6. Spring Boot 负责权限、事务边界、任务编排和 API。
7. React 前端负责网盘、Space、知识库、AI 助手和管理界面。

## 核心业务闭环

~~~mermaid
flowchart LR
  U[用户上传或导入文件] --> M[MinIO 保存对象]
  M --> DB[MySQL 建立文件与 Space 引用]
  DB --> P[解析正文和结构]
  P --> C[结构感知切分]
  C --> E[Embedding]
  E --> Q[Qdrant 建立向量索引]
  Q --> R[RAG_READY]
  R --> S{知识画像开关}
  S -->|关闭| Done[基础 RAG 完成]
  S -->|开启| K[生成画像、问题和质量信息]
  K --> Done
  Done --> Ask[检索问答与引用]
~~~

知识画像是增强 RAG 的可选后续能力，不是文件加入知识库的必要条件。基础成功链路必须完成“文档 → 解析 → 切分 → embedding → 索引”，且 chunk、active ref 和 Qdrant point 对账一致；画像失败不会把已经完成的 RAG 改成失败。

## 核心目标

### 产品目标

- 用统一文件模型连接个人网盘、团队空间和知识库。
- 让用户看到真实状态，而不是“任务返回 success 但没有切片或向量”的伪成功。
- 问答必须提供可预览、可下载、可定位的引用。
- 把知识画像设计成默认开启、可关闭、可审核、可恢复的增强模块。

### 架构目标

- MySQL 是业务状态真相源，外部存储操作通过状态机、幂等键、CAS、对账和补偿收敛。
- 同一文件内容可被多个逻辑节点引用，避免无意义重复存储。
- 长任务可恢复、可重试、可观测，不依赖进程内存维持正确性。
- 配置和凭据分离：业务配置可审计，Secret 通过文件引用注入。

### 工程目标

- 接口遵循 400、401、403、404、409、500 的稳定错误语义。
- Flyway 管理可重复的数据库演进。
- 单元测试、集成测试、真实 Compose E2E 和故障注入共同构成证据链。
- 文档能直接映射到 Controller、Service、Mapper、迁移和前端功能目录。

## 非目标与演进方向

当前不把 GraphRAG、图数据库、消息队列削峰和画像候选发布模型视为已交付能力；它们属于后续演进。现阶段优先保证文件、索引、引用、权限和跨存储一致性闭环，而不是堆叠无法验收的算法名词。

## 技术栈概览

| 层次 | 技术 |
|---|---|
| Web | React、TypeScript、Vite |
| API | Java、Spring Boot、MyBatis、JWT |
| 事务数据 | MySQL、Flyway |
| 对象存储 | MinIO，启用版本控制 |
| 向量检索 | Qdrant |
| 模型服务 | Python、BGE-M3/FlagEmbedding 兼容实现、Rerank、LLM |
| 文档解析 | Python、Tika/结构化解析、OCR/VLM 接口 |
| 部署 | Docker Compose、Nginx、文件型 Secret |

## 成功标准

项目成功不是“接口能返回 200”，而是：

- 用户操作在权限边界内完整闭环；
- 长流程的最终状态能由持久化证据解释；
- 文件、元数据和向量在故障后能够自动或人工触发收敛；
- RAG 的答案可追溯到有效文档；
- 已完成、待完成和待验收不混在同一清单中。
