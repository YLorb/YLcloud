# mq-v5：知识流水线任务迁移

## 目标

将 Knowledge Pipeline 的解析、切块、派生和恢复迁入 knowledge 队列，同时保留旧领域任务只读展示和回滚兼容。

## 依赖与输入

- TASK-20260725-019 已通过观察。
- TASK-20260725-004/005 已定义文件/知识生命周期和 `ACTIVE/NEEDS_REVIEW` 质量状态；Pipeline 任务只驱动这些状态，不创建平行状态机。
- `KnowledgePipelineExecutorService`、Pipeline Service/Recovery/Event 及现有任务表。

## 修改范围与产物

- 为 Pipeline 阶段定义任务类型、依赖关系和稳定 `task_key`。
- 领域记录增加 `async_task_id`；新任务写统一表，旧记录不回填。
- 拆出同步执行核心，Consumer 负责异常传播和结果事务；移除新路径的 `@Async`。
- 使用知识资产/文件版本作为资源栅栏，旧解析结果不得覆盖新文件。
- 大文件阶段拆成有界任务，不在一个 Rabbit delivery 内串行执行无限批次。
- 统一 Pipeline 状态与任务状态映射；旧任务详情提示无 attempts。
- knowledge 默认并发 2、prefetch 1。

## 不包含

- 改变解析器选型、切块算法和知识产品状态定义。
- RAG 消费和 Qdrant Point ID 切换。

## 验收标准

1. 新 Pipeline 任务全部关联统一任务，旧记录仍可列表/详情读取。
2. 解析器崩溃、模型/Qdrant 暂停、租约过期均按统一重试处理。
3. 旧文件版本完成时为 `SKIPPED_STALE`，不发布新版本知识资产。
4. 手工重试复用 taskId，下一次领取版本递增且审计完整。
5. Flag 回切后旧 executor 仅处理旧路径记录。

## 测试与通过

- 覆盖多阶段成功、阶段失败、进程退出、重复事件、文件替换/删除、取消和兼容列表。
- 验证吞吐、单任务时长、Rabbit consumer timeout 和 backpressure。
- 满足 TEST-20260725-002 通用门禁和 `mq-v5` 场景。

## 风险与回滚

- Pipeline 状态和统一状态可能漂移：所有跨表状态更新放在同一 MySQL 事务，并加定时只读审计。
- 回滚关闭 `async.mq.knowledge`，保留新增关联和任务历史。

## 实施与验收记录（2026-07-27）

- 新增 `KNOWLEDGE_PROFILE_DOCUMENT` 与 `KNOWLEDGE_PROFILE_SPACE_FANOUT`，统一路由到 knowledge 队列；默认并发 2、prefetch 1，消息 Payload 仅含领域任务 ID。
- V46 为知识流水线任务增加 `parent_task_id`、`resource_version`、父子唯一约束及统一任务外键；文档版本取 `SpaceRagDocument.consistency_version`，领域任务、统一任务与 Outbox 同事务登记。
- 空间任务改为有界扇出协调器，每个文档子任务独立原子提交，不再在一个 Rabbit delivery 内串行调用整库模型；`(parent_task_id, document_id)` 保证重试扇出幂等。
- 文档 Worker 在模型调用前后、知识资产提交前检查取消和租约；最终写入同时锁定统一任务、尝试版本、领域任务和文档版本/哈希，旧 Worker、已取消任务或被替换文件均不能发布知识资产。
- 手工重试复用原统一 taskId；Flag 开启时旧 `@Async` executor 不执行，旧恢复器跳过已有 `async_task_id` 的任务；Flag 关闭后保留旧记录执行兼容。统一任务列表只从旧知识表读取 `async_task_id is null` 的历史记录，避免双重展示。
- 自动化结果：TASK-020 专项 7 项、知识/统一任务相关回归 27 项通过；全量后端 277 项通过；前端 12 项通过且生产构建成功；开发与 Hub 两份 Compose 配置校验通过。
- 真实环境结果：Flyway 从 V28 连续升级至 V46，V46 `success=1`；应用健康为 `UP`；knowledge 主队列消费者数为 2。真实 API 创建的任务成功关联统一任务，Outbox `SENT` 并产生 RUNNING attempt。
- 故障演练：外部模型长时间未返回时终止 Worker，租约到期后统一任务由 `RUNNING` 恢复为 `RETRY_WAIT`，错误码为 `LEASE_EXPIRED`，重试消息重新进入 knowledge 队列；验收任务、Outbox/attempt 和队列消息已全部清理，knowledge 领域统一任务残留数为 0。
- 运行环境说明：本机 Rabbit 既有 retry queue 的不可变 TTL 为 1000ms，运行态验收使用同值启动；正式部署必须保持 `YLCLOUD_ASYNC_MQ_RETRY_QUEUE_TTL_MS` 与已声明队列一致，变更 TTL 需按运维窗口重建空 retry queue，不能直接用新参数覆盖既有队列。
