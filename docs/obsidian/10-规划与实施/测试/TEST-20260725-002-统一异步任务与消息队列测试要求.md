# 统一异步任务与消息队列测试要求

## 1. 目标

为 `mq-v1` 至 `mq-v6` 提供不可跳过的正确性、故障恢复、安全和发布门禁。每个版本只在本版本必需场景和全部通用回归通过后才能 commit/push 和部署下一版。

本文件是异步/MQ 专项门禁，不替代 TEST-20260725-001。任务中心权限、Space/文件/知识状态、Agent 授权、审计、备份和最终发布还必须满足平台专项要求；统一实施顺序见 `.plans/implement-unified-knowledge-platform.todo.md`。

## 2. 测试环境

- Java 17、项目固定 Maven/Node 版本。
- MySQL 和 RabbitMQ `4.3.4-management` 的隔离测试实例；优先 Testcontainers，Compose 验收使用与生产相同拓扑。
- 涉及领域时接入隔离 MinIO、Qdrant、model-service/解析器 stub 或真实测试实例。
- 测试时缩短租约/心跳/重试可加速，但至少有一组按生产默认 120s/30s/60s 演练。
- 所有测试数据使用唯一前缀并可清理，不连接生产资源。

## 3. 通用单元测试

1. 所有合法/非法状态转换。
2. `attempt_version` 只在成功领取时递增。
3. 创建 `task_key` 对相同业务字段稳定、不同动作不冲突。
4. 异常到 retryable/fatal/stale 的映射和未知异常默认策略。
5. 错误消息脱敏、长度截断和堆栈不入库。
6. 创建者、Space owner/admin、系统管理员和无权用户的 retry/cancel 权限矩阵。
7. 资源版本比较和 `SKIPPED_STALE`。
8. Point ID 固定测试向量、UTF-8、不同 `spaceFileId` 隔离（从 `mq-v6` 开始）。

## 4. 数据库与事务一致性

| 场景 | 必须断言 |
|---|---|
| 业务事务回滚 | 领域数据、task、outbox 全部不存在 |
| Rabbit 不可用 | 业务和 task/outbox 已提交；状态 `PENDING_PUBLISH` |
| Confirm ACK | Outbox `SENT`，任务进入可消费状态 |
| Confirm NACK/超时/Return | Outbox 保留并可补发，不伪造 `SENT` |
| 多 Publisher 抢同 Outbox | 只有一个有效领取；重复发布仍可被消费去重 |
| 重复 task_key | 返回/复用原任务，不产生两个有效业务动作 |
| 结果提交前进程退出 | Broker 可重投或租约恢复，最终不丢任务 |
| ACK 前结果事务失败 | 不 ACK，数据库无半完成状态 |

Flyway 检查：

- 空库能从头迁移。
- 现有版本库只向前迁移。
- 旧应用能在新增 schema 上启动或明确由发布门禁阻止不兼容版本。
- 任何自动回滚均不得改变 Flyway history。

## 5. 消费、Inbox 与幂等

1. 同一 `messageId` 串行和并发投递 10 次，只产生一个有效 attempt/副作用。
2. 不同 `messageId` 指向相同 `expectedAttemptVersion`，只有一个领取成功。
3. 领取后消息重复到达且租约有效，重复消息安全 ACK/忽略。
4. 消息 schema 不支持、字段缺失、不可路由时进入 DLQ并告警。
5. Consumer 在结果事务提交前不得 ACK。
6. 领域副作用已成功但 ACK 丢失时，重投不产生重复外部结果。
7. 人工重试创建新 messageId，不重放旧 DLQ。

## 6. 租约与尝试历史

| 场景 | 期望 |
|---|---|
| 正常长任务 | 每 30s 左右续租，2min 租约不误过期 |
| Worker 停心跳 | 到期后当前 attempt 关闭 |
| 前 3 次租约到期 | `RETRY_WAIT`，1min 后新领取且版本 +1 |
| 第 4 次到期/失败 | `FAILED`，恢复器不再领取 |
| 旧 Worker 恢复 | 心跳、成功、失败更新均为 0 行，不能覆盖新 Worker |
| 人工重试 | 原 taskId；状态 `FAILED→RETRY_WAIT`；下一领取版本 +1；审计完整 |

每个 attempt 必须能核对触发类型、Worker、lease token（UI 可掩码）、开始/心跳/完成、耗时、错误码、原因和下次重试。

## 7. 取消测试

- `PENDING_PUBLISH`、`PENDING`、`RETRY_WAIT` 直接取消为 `CANCELED`。
- `RUNNING` 写 cancel request，Worker 在每个安全检查点退出。
- 取消和成功并发时只有一个终态。
- 取消后旧 Worker 的领域写和任务完成被版本/租约栅栏拒绝。
- 无权用户得到 403；授权路径均有审计。
- 前端固定显示 `CANCELED`，不显示 `CANCELLED` 或泛化失败。

## 8. 分域版本验收矩阵

### mq-v1

- `ASYNC_DEMO` 成功、retryable、fatal、取消、租约崩溃和重复消息。
- API 新旧合并分页，详情 attempt 时间线，权限按钮。
- Rabbit 停止创建任务、恢复补发。
- Outbox/Inbox/清理/指标/告警。
- `deploy.sh` 全矩阵。

### mq-v2

- 重复扫描、对象不存在、部分清理、MinIO/Qdrant 暂停。
- 删除前资源版本变化导致 stale，不能误删新资源。
- cleanup/maintenance Flag 独立切换且不双跑。

### mq-v3

- 模型限流/超时、向量失败、来源删除/更新、取消。
- 用户敏感内容不进入消息、错误摘要和普通日志。
- provider 调用幂等或重复成本有证据。

### mq-v4

- 消息创建与 Outbox 原子性。
- 重复 Workflow 回调/模型回答不产生双结果。
- 消息编辑、删除、取消和迟到结果。
- Chat 延迟和积压告警。

### mq-v5

- Pipeline 多阶段、解析器崩溃、阶段恢复、文件替换。
- 旧任务只读兼容、新任务 attempts。
- 大文件拆分和 backpressure。

### mq-v6

- Point ID 固定向量、逻辑文件隔离、内容变更、重命名/移动。
- 新点写入/验证/旧点清理过程可重入。
- 批量父子任务汇总、局部失败、取消和续批。
- 六域全开，无新业务重型 `@Async` 执行。

## 9. API 与前端

- 列表必须做数据库级统一分页和稳定排序，跨页无重复/遗漏。
- 筛选：状态、域、类型、创建者、Space、时间。
- 详情轮询在终态停止；活跃状态能看到心跳和下次重试变化。
- `FAILED`/`RETRY_WAIT` 显示安全且具体的原因；旧任务提示无历史。
- retry/cancel 按钮状态与后端 `canRetry/canCancel` 一致，不能仅靠前端隐藏做授权。
- 父子任务、`SKIPPED_STALE`、`CANCELED` 的颜色/文案和无障碍标签可识别。

## 10. 性能与容量

每域建立基线并保存测试数据：

- 创建任务 TPS、Outbox 发布延迟 p50/p95/p99。
- queue ready/unacked、oldest age、consumer utilization。
- 任务端到端延迟、执行耗时、重试率、失败率、租约过期率。
- Worker CPU/内存、数据库连接/锁等待。

至少进行：

- 每域 1,000 个轻任务突发。
- RAG/Pipeline 代表性大文件批量。
- Rabbit 停止 10 分钟后的 Outbox 恢复削峰。
- Worker 滚动退出/重启期间的在途任务恢复。

不得以无限提高 listener 并发解决积压；需同时验证下游限流和数据库连接容量。

## 11. 安全与运维

- Rabbit AMQP 不对公网发布，Management 仅 `127.0.0.1`。
- guest 不可远程登录；应用账号不能做管理操作。
- secret 不出现在 Git diff、Compose config 输出、应用日志和部署日志。
- DLQ > 0、Outbox > 60s、consumer=0、oldest ready > 5min 的告警可触发。
- 保留器只删除超过配置时长的终态/已发送数据，不删除活跃、未发 Outbox 或未处置 DLQ。

## 12. `deploy.sh` 故障矩阵

| 注入点 | 预期 |
|---|---|
| 参数非法/锁冲突/磁盘不足 | 更新前失败，无容器变化 |
| Compose config 非法/secret 缺失 | 更新前失败 |
| 目标镜像不存在/拉取失败 | 旧服务保持运行 |
| Rabbit 首装不健康 | app/frontend 不更新 |
| app 迁移或健康失败 | 自动恢复旧 app；frontend 保持旧版 |
| app 冒烟失败 | 自动恢复旧 app |
| frontend health/HTTP 失败 | app 和 frontend 均恢复旧镜像 |
| 容器未重建或镜像 digest 不符 | 判失败并回滚 |
| restart count 增长 | 判失败并保留诊断 |
| INT/TERM | trap 回滚已变更服务 |
| 回滚健康失败 | 非零专用退出码，保留日志，不修改 current-version |
| 成功 | current-version 原子更新，输出 digest/日志/耗时 |

用 ShellCheck 校验脚本。脚本源码扫描不得出现 `down -v`、volume 删除、Flyway undo、数据库 restore 和无目标 `docker compose pull`。

## 13. 版本发布门禁

每个版本必须同时满足：

1. 后端单元/集成测试通过。
2. 前端测试（如存在）和生产构建通过。
3. Flyway 空库/升级检查通过。
4. Compose 健康与该版本 smoke 通过。
5. 该版本故障注入通过，旧 Flag 回切通过。
6. 无 secret、无未解释高危扫描结果。
7. 文档状态、配置、迁移号、测试证据和已知风险已回写。
8. 独立 commit 和 push 成功后，才开始下一版本。

## 14. 最终通过标准

- 六个任务的验收项全部有自动化或可复现证据。
- 所有新异步业务都能从统一任务中心查看、重试和取消。
- 重复投递、进程崩溃、Rabbit 中断、下游超时和应用降版均不丢任务、不产生不可解释重复副作用。
- `mq-v6` 观察窗口内无旧执行路径双跑、无 Point ID 互相覆盖、无未处置 DLQ。
- TASK-20260725-015 汇总 TEST-20260725-001 与本文件证据后，才能判定整个平台可发布。
