# mq-v6：RAG 迁移与最终切换

## 目标

迁移 Space RAG 索引/删除/批量任务，启用稳定 Point ID、逻辑文件隔离和资源版本栅栏；完成所有异步域最终切换并进入旧执行路径移除观察期。

## 依赖与输入

- TASK-20260725-020 已通过观察。
- TASK-20260725-004 已定义 Space 逻辑文件、移出即停止检索和清理派生物的领域规则；本任务负责统一任务执行、Point ID 与最终切换。
- `RagTaskExecutorService`、`SpaceRagService`、`QdrantVectorStoreService`、`SpaceRagTaskService`、批量索引和一致性服务。
- Space 逻辑文件以 `spaceFileId` 独立展示和管理。

## 修改范围与产物

- 定义单文件索引、删除、重建、一致性修复和批量父任务/子任务。
- Space 批量任务只做扇出和聚合，单文件为独立消息；限制一次扇出批量并支持续批。
- 新 `task_key` 使用稳定业务字段；同一活动范围不双创建。
- 资源键至少包含 `spaceId + spaceFileId`，每次内容/删除动作推进版本。
- 将 Point ID 改为：
  `point-id-v1|spaceId|spaceFileId|fileHash|chunkIndex` 的 UTF-8 确定性 UUID。
- 为旧 Point ID 制定兼容清理：新版本写入成功并验证后，再按逻辑文件过滤删除旧点；失败保留旧可用索引并重试。
- Consumer 调用同步核心并向上抛结构化错误，不能在领域服务中吞掉异常后仍 ACK。
- RAG 默认并发 2、prefetch 1；删除/索引以资源版本保证顺序。
- UI 完成所有域筛选、详情时间线和父子任务展示。
- 开启 `async.mq.rag` 后观察；确认所有域稳定再永久关闭旧 `@Async` 创建入口和共享恢复领取。

## 不包含

- 立即删除旧领域表/列。
- Qdrant 集群升级或 collection staging/alias 架构重做。
- 历史任务回填。

## 验收标准

1. 同一 `spaceFileId/fileHash/chunkIndex` 重试 Point ID 完全一致。
2. 同一物理文件的不同 `spaceFileId` Point ID 不同，删除互不影响。
3. 文件内容更新得到新 ID；重命名/移动不改变 ID。
4. 删除高版本后，迟到索引任务 `SKIPPED_STALE`，不能复活向量。
5. 批量父任务能准确汇总成功、失败、取消，单个失败不丢其他子任务。
6. Rabbit 中断、Worker 崩溃、Qdrant 超时均能按租约/重试恢复。
7. 所有异步任务的新创建路径均通过 MQ；观察期后没有业务 `@Async` 重型执行。

## 风险与回滚

- Point ID 切换可能产生双份点：使用“写新并验证 → 清旧”的可重入步骤及指标核对。
- 回滚关闭 `async.mq.rag` 并恢复旧镜像；数据库和 Rabbit 拓扑不降级。
- 旧 Point 清理必须在回滚窗口后独立执行，不能与首轮切换绑在一个不可逆事务。

## 实施与验收记录（2026-07-27）

- RAG 新建路径已统一为 `RAG_INDEX_FILE`、`RAG_REBUILD_FILE`、`RAG_DELETE_FILE` 和 `RAG_SPACE_FANOUT`；领域任务、统一任务和 Outbox 同事务登记。单文件资源键为 `rag-file:{spaceId}:{spaceFileId}`，空间父任务使用 `rag-space:{spaceId}:{taskId}`。
- V47 增加统一任务父子关系、RAG 父任务/统一任务关联、资源版本、删除标记和有界扇出游标；空间任务每批最多处理 100 个逻辑文件，子任务独立提交，父任务汇总 `SUCCESS/PARTIAL/FAILED/CANCELED`。
- Point ID 固定为 `UUID.nameUUIDFromBytes("point-id-v1|spaceId|spaceFileId|fileHash|chunkIndex".getBytes(UTF_8))`。固定向量 `(9,42,"abc123",0)` 为 `7f5033b0-dfae-3368-8975-4bd8eb456aa1`。新点先写入并校验，数据库版本围栏提交成功后才删除旧点。
- 文件索引提交同时锁定统一任务 attempt、领域任务关联、逻辑文件、资源版本和 `consistency_async_task_id`；删除会推进版本并跳过旧索引。失败文档可由更高优先级重建安全接管 `CLEANUP_PENDING/CLEANING`，旧清理任务随后因版本/关联不匹配失效。
- RAG 队列默认并发 2、全局 prefetch 1；六个迁移开关在两份 Compose 和示例环境中默认开启。`async.mq.rag=false` 时旧执行器继续兼容处理，Flag 开启时旧 `@Async` 入口 no-op，避免双跑。
- 统一任务页面增加父任务标识、子任务入口和详情父任务字段；旧 RAG 记录仅在 `async_task_id is null` 时合并展示，避免同一任务重复出现。
- 真实 Win10 Docker 验收：Flyway V46→V47 成功，应用健康 `UP`，RAG 主队列消费者数 2。上传 README 后领域任务和统一任务均为 `SUCCESS`，数据库 21 条活动引用对应 Qdrant 21 个 `pointIdVersion=v1` 点。
- 逻辑文件隔离实测：同一个 `fileUuid` 的两个 `spaceFileId` 各生成 21 个点，Point ID 交集为 0；删除其中一个后其点数为 0，另一个仍为 21。
- 版本围栏实测：对同一逻辑文件先重建再立即删除，重建任务为 `SKIPPED_STALE`，高版本删除任务为 `SUCCESS`，删除点数为 0，向量未复活。
- 父子任务实测：空间父任务创建两个文件子任务，子任务的 `parent_task_id` 均指向父统一任务；父任务终态 `SUCCESS`，汇总 `total=2/success=2/failed=0`。
- Rabbit 故障演练：Broker 离线时任务保持 `PENDING_PUBLISH`、Outbox `PENDING` 并记录连接拒绝；恢复后同一 Outbox 自动补发为 `SENT`，任务 attempt 1 最终 `SUCCESS`。

- 验收中发现并修复 Apache HTTP 客户端读取 Qdrant JSON 偶发截断的问题，Qdrant REST 校验统一使用带连接/读取超时的 `SimpleClientHttpRequestFactory`；同时保留业务异常 cause 链和任务结构化日志。
