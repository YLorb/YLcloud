# 统一异步任务与 RabbitMQ 消息队列

## 1. 背景

当前项目以 `ThreadPoolTaskExecutor`、`@Async("ragTaskExecutor")`、定时恢复器和领域任务表承载异步工作。它能防止同一任务记录被并发领取，但缺少统一的可靠投递、租约续期、跨进程消费、完整尝试历史和通用取消协议；进程在“业务事务已提交但任务未开始”或 `RUNNING` 中途退出时，需要各领域自行恢复。

## 2. 目标

1. 本需求纳入范围内的六个存量重型异步域统一登记到 MySQL，并通过 RabbitMQ 触发对应执行函数。
2. 使用事务 Outbox 保证“业务数据、任务记录、待发送消息”本地事务一致。
3. 在 RabbitMQ 至少一次投递下，通过 Inbox、任务领取 CAS、租约和资源版本保证幂等。
4. 统一任务状态、自动重试、人工重试、取消、失败原因、权限和保留策略。
5. 分六个可独立发布和回滚的版本迁移现有全部异步任务。
6. 提供一个 Linux 部署脚本的实现契约，覆盖拉取、更新、健康检查、冒烟验证和异常自动回滚。

## 3. 范围

### 3.1 纳入范围

- 物理文件清理和维护修复任务。
- 用户记忆提取、画像生成和向量索引任务。
- 知识问答异步查询和 Workflow 消息生命周期任务。
- Knowledge Pipeline 解析与派生任务。
- Space RAG 索引、删除、批量扇出和一致性修复任务。
- 统一任务列表、详情、尝试时间线、人工重试和取消界面。
- RabbitMQ、MySQL 表、Spring AMQP 配置、监控、保留清理和单脚本部署规格。

定时扫描器和一致性协调器可以保留，但只能发现工作、创建统一任务及 Outbox，不能继续直接执行重型业务。

### 3.2 不纳入范围

- 历史领域任务向新表回填。
- RabbitMQ 三节点高可用、跨机房容灾和零停机滚动发布。
- 自动回滚或覆盖已执行 Flyway 迁移。
- 强杀正在运行的线程。
- 在消息正文中传递文件内容、密钥或大段业务数据。

## 4. 已确认的产品规则

| 主题 | 定稿 |
|---|---|
| 消息中间件 | RabbitMQ，生产首期单节点 |
| 可靠性 | MySQL 为任务事实源；事务 Outbox；Publisher Confirm；消费者手动 ACK；至少一次投递 |
| 队列 | 按 cleanup、maintenance、memory、chat/workflow、knowledge、rag 分域 |
| 自动尝试 | 总计最多 4 次（含首次），固定间隔 1 分钟 |
| 失败终态 | 第 4 次失败或租约到期后进入 `FAILED`，只能人工重试 |
| 租约 | 2 分钟，Worker 每 30 秒续期 |
| 人工重试 | 复用原 `taskId`；`FAILED → RETRY_WAIT`；新 Outbox；下一次领取 `attempt_version + 1` |
| 取消 | 前端显示 `CANCELED`；等待任务直接取消；运行任务协作式取消 |
| 详情 | 展示每次失败/重试原因、Worker、租约、时间和操作审计 |
| Point ID | `point-id-v1|spaceId|spaceFileId|fileHash|chunkIndex`，UTF-8 稳定计算 |
| 逻辑文件 | 同一物理文件在不同 `spaceFileId` 下拥有独立向量点 |
| 数据保留 | 终态任务、尝试和已发送 Outbox 默认保留 3 天，可配置 |
| 权限 | 创建者、Space owner/admin 或系统管理员可人工重试/取消；系统任务仅系统管理员 |
| 迁移 | 六版本渐进迁移；领域 Feature Flag 支持共存和回切 |
| 部署 | 每版本独立测试、提交并推送；一个 Linux 脚本完成发布、验证和自动回滚 |

## 5. 状态与可见性

统一状态至少包含：

`PENDING_PUBLISH`、`PENDING`、`RUNNING`、`RETRY_WAIT`、`SUCCESS`、`FAILED`、`CANCELED`、`SKIPPED_STALE`。

前端列表显示当前状态和最近失败摘要；详情显示追加写入的尝试时间线。旧 `space_rag_task` 和 `space_knowledge_pipeline_task` 不回填，继续以只读兼容数据源合并展示，且明确标记“旧任务无尝试时间线”。

## 6. 一致性与幂等验收

1. RabbitMQ 不可用时，业务事务仍可提交，任务保持 `PENDING_PUBLISH`，恢复后补发。
2. 同一 `messageId` 重复投递不能重复领取任务。
3. 同一任务同时只能存在一个有效租约；旧 Worker 的心跳、完成和失败写入必须被 `attempt_version + lease_token` 拒绝。
4. 租约到期任务由恢复器在事务中进入 `RETRY_WAIT` 或 `FAILED`，并在需要重试时生成新 Outbox。
5. 资源低版本任务只记 `SKIPPED_STALE` 并 ACK，不得覆盖或复活高版本资源。
6. Qdrant 重试使用相同 Point ID；不同 `spaceFileId` 不得相互覆盖。
7. 消费结果事务提交后才能 ACK；异常退出后可由重投或租约恢复继续。

## 7. 发布与回滚验收

1. `mq-v1` 至 `mq-v6` 每版都能独立部署、验证、提交和推送。
2. 应用回滚只切换旧镜像和 Feature Flag；数据库保持向前兼容，不自动降迁移。
3. 单脚本仅接受版本参数，具备互斥锁、预检、定向拉取、容器重建核验、健康检查、冒烟验证、日志、状态记录和失败自动回滚。
4. 脚本不得执行 `docker compose down -v`、删除持久卷、破坏性数据库回滚或自动清理未处理 DLQ。
