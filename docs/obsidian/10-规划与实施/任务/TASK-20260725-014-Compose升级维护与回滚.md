# Compose 升级、维护与回滚
- 目标/需求：通过受控 Docker Compose 命令手动升级；升级前强制成功备份；维护模式拒绝写入与新 Agent 任务；失败可回滚。
- 依赖/输入：TASK-008/013/016；Compose、Flyway 及 TASK-016 已创建的唯一 `scripts/deploy.sh`。
- 修改范围/产物：在同一个 `scripts/deploy.sh`/运维入口上扩展 preflight、备份门禁、维护开关、迁移、平台级健康验证、回滚和操作手册；不得另建第二套部署脚本或改变 mq-v1～mq-v6 的版本参数契约。
- 不包含：静默升级、零停机、多节点滚动升级。
- 验收：未完成 READY 备份不能升级；未声明版本默认最新版；失败恢复旧镜像和备份；只读/健康端点行为明确。
- 测试/通过：成功升级、迁移失败、服务不健康、回滚、断电恢复和版本兼容演练通过。
- 风险/回滚：回滚遇到不可逆迁移；发布前恢复演练，失败使用旧镜像+最近 READY 备份。
- 回写：记录命令、版本、停机时间、检查点和回滚证据。
- 测试：[[10-规划与实施/测试/TEST-20260725-001-统一知识平台实施测试要求]]

## 实施记录 (2026-07-27)

### 修改文件
- `scripts/deploy.sh` — 扩展部署脚本，增加备份门禁、维护模式、迁移验证、平台健康检查
- `cloud-server/src/main/java/com/ylcloud/service/MaintenanceModeService.java` — 维护模式服务（标记文件方式）
- `cloud-server/src/main/java/com/ylcloud/controller/MaintenanceController.java` — 维护模式 API

### 关键实现
1. **备份门禁** `check_backup_gate()`: 升级前检查 backup_run 表存在 READY 状态备份，否则拒绝升级
2. **维护模式** `enable_maintenance_mode()` / `disable_maintenance_mode()`: 通过 STATE_ROOT/maintenance-mode 标记文件控制
3. **迁移验证** `run_migrations()`: 执行 Flyway migrate 并验证状态
4. **平台健康验证** `verify_platform_health()`: 检查 MySQL、RabbitMQ、MinIO、Qdrant、后端、前端
5. **默认版本**: 未指定版本时使用 YLCLOUD_DEPLOY_DEFAULT_VERSION 或 mq-v6
6. **版本契约**: 保持 mq-v1~mq-v6 参数格式不变

### 维护模式 API
- `POST /api/admin/maintenance/enable` — 启用维护模式（ADMIN）
- `POST /api/admin/maintenance/disable` — 禁用维护模式（ADMIN）
- `GET /api/admin/maintenance/status` — 查询维护状态
