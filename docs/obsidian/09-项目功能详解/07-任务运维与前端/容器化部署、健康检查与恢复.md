# 容器化部署、健康检查与恢复

## 产品目标

项目应在一套可重复环境中启动全部依赖，自动迁移数据库、初始化存储，并在重启后保留文件、索引和任务。健康检查要反映依赖是否可用，而不只是进程存在。

## 七服务组成

MySQL、MinIO、Qdrant、model-service、document-parser-service、Spring Boot app、frontend/Nginx。docker-compose.yml 用于本地构建，docker-compose.hub.yml 使用已发布镜像。持久卷保存数据库、对象、向量和模型缓存。

## 启动依赖

1. 数据服务启动并通过健康检查。
2. 应用连接 MySQL，Flyway 执行至最新迁移。
3. MinioStorageInitializer 创建 bucket、启用版本控制并禁止匿名访问。
4. QdrantCollectionInitializer 创建 collection 和 payload index。
5. 模型/解析服务 readiness 可用。
6. 应用恢复超时任务并执行 RAG 对账。
7. Nginx 提供静态前端与 /api 代理，RAG 长请求使用合理超时。

## 健康的层次

| 层次 | 示例 |
|---|---|
| 进程 | 容器运行、端口监听 |
| 依赖 | MySQL ping、MinIO live、Qdrant healthz |
| 能力 | embedding 模型已加载、parser 依赖可用 |
| 业务 | 上传→解析→索引→查询 smoke |

只有前三层不能完全证明业务链路。

## 恢复

容器重启后：

- Flyway 重复启动幂等；
- 分片租约过期后继续上传/合并；
- cross_store_operation 可被恢复服务接管；
- RAG BUILDING/清理状态由超时回收和对账收敛；
- 画像 RUNNING 超时任务被回收；
- physical cleanup 未完成任务继续；
- MinIO/Qdrant/MySQL 持久卷保持数据。

## Secret 与网络

JWT/模型 Key 通过 .secrets 文件挂载，容器不注入对应明文环境变量。除前端外，默认宿主机端口绑定 127.0.0.1；生产由反向代理、HTTPS 和防火墙控制入口。

## 发布与风险

发布前应运行后端、前端、Python、迁移和 Compose smoke 的统一门禁。目标服务器仍需完成 Compose v2、Hub 拉取、七服务健康、备份恢复和 Secret 轮换验收。Qdrant 与 Flyway/MySQL 版本兼容必须在升级前收口。
