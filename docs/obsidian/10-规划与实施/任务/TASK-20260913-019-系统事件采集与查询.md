# 系统事件采集与查询

- 目标：建立通用系统事件并接入 `/admin/events` 的系统事件标签，覆盖登录、上传/下载、任务开始/终止/完成的成功和失败。
- 前置与输入：TASK-20260913-009；登录、文件流、统一任务现有服务与安全审计模型。
- 产物：`system_event` 迁移、统一脱敏写入服务、幂等 eventKey、管理员分页/详情 API、30 天可重入清理、前端筛选/详情。
- 不包含：手工伪造事件、替换安全审计、存储文件内容或 Secret；日志采集平台不是本轮范围。
- 验收：同一次操作各阶段/结果不重复；流中断不记成下载成功；失败可查询；30 天前记录清理、边界日保留；审计页独立可用。
- 测试：事件类型/成功失败、重复事件、敏感值脱敏、事务失败、清理边界、服务端权限、前后端筛选和 E2E；通过才完成。
- 风险与回滚：同步事件落库可能影响主链路；实现需定义失败降级与告警，关键安全审计不得失效；可停新事件采集，保留历史表。
- 回写：实现 Agent 生成完整用例和独立记录并回写状态；下游 [[10-规划与实施/测试/TEST-20260913-002-管理后台真实API与节点绑定测试要求]]。
