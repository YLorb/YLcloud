# mq-v3：用户记忆任务迁移

## 目标

将用户记忆提取、画像派生和记忆向量索引迁入 memory 队列，保证同一用户/会话资源的版本顺序和取消后旧结果不可回写。

## 依赖与输入

- TASK-20260725-017 已通过观察。
- `UserMemoryExtractionService`、`UserMemoryService` 及相关 mapper/vector 实现。

## 修改范围与产物

- 定义 `MEMORY_EXTRACT`、`MEMORY_PROFILE_BUILD`、`MEMORY_VECTOR_INDEX` 等任务类型。
- 业务提交记忆原始数据时，同事务创建 task/outbox；消息只带 ID。
- 使用 `user-memory:{userId}:{sourceId}` 形式稳定资源键和单调版本。
- 把 `@Async`/直接 executor 调用改为 Feature Flag 双路径；消费者调用同步核心函数。
- 模型/向量调用使用可重试错误分类；权限丢失、来源删除、内容非法为 fatal/stale。
- 详情错误信息不得泄露对话正文、模型请求或密钥。
- memory 默认并发 2、prefetch 1。

## 不包含

- 改变记忆抽取算法、Prompt 或画像产品规则。
- Chat/Workflow 消息迁移。

## 验收标准

1. 相同业务事件重复提交只产生一个有效任务。
2. 用户删除/更新后，旧版本抽取或向量结果为 `SKIPPED_STALE`。
3. 模型临时失败按 1 分钟重试，最多 4 次；fatal 不自动重试。
4. 取消运行任务后，模型返回结果不能落成有效画像。
5. Flag 关闭可回到旧路径，不发生 MQ 和 `@Async` 双执行。

## 测试与通过

- 并发更新、重复消息、模型超时/限流、Qdrant 不可用、取消和租约过期。
- 断言敏感内容不进入消息、任务错误摘要和普通日志。
- 满足 TEST-20260725-002 通用门禁和 `mq-v3` 场景。

- 回滚仅关闭 `async.mq.memory` 并部署旧镜像，新增表不删除。

## 实施回写

- 新增 `async.mq.memory` 独立开关和 memory 队列监听，默认并发 2、prefetch 1；开关关闭时保留原本地 executor/定时恢复路径，旧路径会避让仍处于活动态的统一任务。
- 抽取提交在同一事务中写 `user_memory_extraction_task`、`MEMORY_EXTRACT` 与 outbox；任务消息只含抽取记录 ID，资源键为 `user-memory:{userId}:{sourceMessageId}`，不包含对话正文。
- 记忆处理拆为 `MEMORY_EXTRACT → MEMORY_PROFILE_BUILD → MEMORY_VECTOR_INDEX`，向量删除使用 `MEMORY_VECTOR_DELETE`。画像与向量任务使用用户 ID、规范化键哈希和单调版本构造稳定资源键。
- Flyway V44 为抽取记录和记忆条目增加来源/画像/向量统一任务关联与 `async_version` 栅栏；更新、遗忘、清空和替代旧记忆都会推进版本并清除旧任务关联。
- 模型返回后、画像写入前以及 Qdrant 副作用前后均执行取消/租约检查；来源删除/更新、父抽取任务失败或取消、版本变化均以 stale 收敛，旧结果不能激活画像。
- 模型、Qdrant 错误统一使用脱敏摘要；普通日志只记录任务/记忆 ID 和异常类型，不记录对话正文、模型响应、请求或密钥。
- Qdrant Point ID 继续复用稳定 `user-memory-{memoryId}` 名称型 UUID。模型接口暂无 provider request key，模型调用采用 at-least-once；候选唯一键可防止数据库重复画像，但极端租约失败仍可能产生重复模型调用成本，作为已知风险保留。

## 验收结果

- TASK 专项与关联测试 31 个、后端全量 262 个、前端 12 个全部通过；Spring Boot 与 Vite 生产构建成功。
- Win10 Docker 中已有 V43 数据库成功前滚 V44，应用健康为 `UP`；真实 Profile→Vector 链的两个任务均 attempt 1 成功，model-service `/embed` 返回 200，Qdrant 对应记忆点计数为 1。
- RabbitMQ 停机时 Profile 任务保持 `PENDING_PUBLISH`，共经历 13 次发布尝试但未执行 Worker；恢复后 Profile 与 Vector 均 attempt 1 成功，outbox/inbox 收敛为 `SENT/PROCESSED`。
- Flag=false 回切验收中候选由旧路径激活为 `ACTIVE/READY`，画像/向量任务关联均为空，统一 memory 任务新增数为 0。
- 本轮正常样本每条候选产生 1 个 DB-only Profile 任务和 1 个 Vector 任务，Worker 重试率 0；相较旧路径仍为 1 次 embedding 调用，未增加向量模型调用成本。该小样本仅用于功能门禁，不作为生产延迟基线。
