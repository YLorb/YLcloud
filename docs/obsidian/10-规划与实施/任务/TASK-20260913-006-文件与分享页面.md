# 文件与分享页面

## 目标与需求覆盖

完成 `/admin/file-list` 与 `/admin/shares` 的资源治理前端原型，覆盖筛选、详情、分页和临时处置操作。

## 前置依赖与输入

- 前置：TASK-20260913-001。
- 输入：现有 AdminFilesPage、SharesPage、文件与分享领域类型和统一文件展示工具。
- 下游测试：[[10-规划与实施/测试/TEST-20260913-001-管理后台前端页面验收要求]]。

## 修改范围与预期产物

1. 文件页提供文件名/UUID/所有者/类型/状态/时间筛选、分页、详情、导入表单和删除确认。
2. 分享页提供分享 ID/源文件/分享人/状态/有效期筛选、分页、详情和撤销确认。
3. 统一大小、时间、所有者、未知类型和过期状态显示；超长名称和 UUID 可复制且不破坏布局。
4. 默认空数据时仍展示字段、筛选和操作；fixture 可验证详情和临时操作。

## 明确不包含

- 真实导入、下载、预览、删除、分享撤销、对象存储访问或跨用户资源授权。

## 验收标准

- 两页均具备完整数据管理结构，不再只有空表头。
- 临时删除/撤销只影响当前内存集合，刷新恢复；提示不宣称服务器已修改。
- 长文件名、缺失所有者、过期时间为空和未知类型均安全展示。

## 测试、风险与回滚

- 测试：组合筛选、分页、格式化、复制、详情、导入校验、删除/撤销确认、空/错误数据和窄屏表格。
- 风险：资源操作具有高误导性；演示标识和确认文案不可关闭。
- 回滚：恢复现有 AdminFilesPage/SharesPage；不修改文件和分享 API。
- 实现 Agent/LLM 必须生成完整测试用例和独立测试记录，并回写状态与证据。
