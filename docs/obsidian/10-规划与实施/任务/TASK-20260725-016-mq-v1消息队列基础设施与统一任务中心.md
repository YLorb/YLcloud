# mq-v1：消息队列基础设施与统一任务中心

## 目标

搭建不迁移重型业务的 MQ 基座：RabbitMQ、统一任务四表、Outbox Publisher、统一消费协议、租约/重试/取消服务、API/UI 基础视图和 Linux 单脚本部署。使用一个无副作用的示范任务证明端到端闭环。

## 依赖与输入

- [[10-规划与实施/ADR-20260725-002-RabbitMQ统一异步任务架构]]
- TASK-20260725-002 已完成；任务列表、详情、人工重试和取消必须复用统一 `AccessSubject`/资源动作授权，不建立第二套 ADMIN 豁免。
- Spring Boot 3.3.5 / Java 17 / MyBatis / MySQL / Flyway。
- `docker-compose.yml`、`docker-compose.hub.yml`、`.env*.example`。
- 现有 `/api/async`、前端 `TasksPage` 和领域任务兼容查询。

## 修改范围与产物

1. 后端依赖和配置
   - 增加 `spring-boot-starter-amqp`。
   - 增加 Rabbit 地址、vhost、secret、Publisher Confirm/Return、listener manual ACK、分域并发/prefetch、租约 120 秒、心跳 30 秒、重试 60 秒、最大尝试 4、保留 3 天配置。
   - 所有默认值可通过环境变量覆盖。
2. Flyway
   - 新增 `async_task`、`async_task_attempt`、`mq_outbox`、`mq_inbox`。
   - 给首批关联表新增可空 `async_task_id`；其余领域列可在对应版本增加。
   - 迁移只能 expand，禁止修改旧版本。
3. 统一任务模块
   - Task 创建幂等、状态机、领取 CAS、心跳续约、完成/失败、租约恢复、人工重试、协作取消、资源版本检查。
   - 异常分类器和脱敏/截断器。
   - Outbox 批量领取、Confirm/Return 状态更新、退避补发。
   - Inbox 去重和统一 Consumer 模板。
4. Rabbit 拓扑
   - 声明 ADR 中全部 exchange/queue/binding/retry/DLQ，即使后续域消费者尚未开启。
   - 容器固定 `rabbitmq:4.3.4-management`，持久卷、healthcheck、内部网络、localhost 管理端口和 secret。
5. API/UI
   - 新旧任务合并分页列表。
   - 新任务详情和 attempts 时间线。
   - retry/cancel API、权限判定、`CANCELED`/`RETRY_WAIT`/`SKIPPED_STALE` 展示。
   - 旧任务显示兼容标识，不伪造尝试历史。
6. 示范任务
   - `ASYNC_DEMO` 只读取 task payload 中的短文本/延迟参数并写结构化结果，不产生外部副作用。
   - 提供仅开发/测试可用的创建入口。
   - 支持模拟成功、可重试失败、致命失败、超时、取消和重复消息。
7. 可观测和清理
   - Actuator/Rabbit health、任务和队列指标、结构化日志。
   - 终态记录批量保留清理；默认 3 天。

建议新代码按 `async/task`、`async/mq`、`async/worker` 分层，领域执行函数通过注册表按 `taskType` 定位；禁止 Listener 内写大段领域分支。

## 单一 Linux 部署脚本实现规格

产物固定为仓库根目录可执行文件 `scripts/deploy.sh`，调用方式只有：

```bash
./scripts/deploy.sh mq-v1
```

传入旧版本如 `./scripts/deploy.sh mq-v1` 也代表应用回滚。脚本不得要求操作者拼接 `docker compose pull && up -d`。

该文件是仓库唯一部署入口。后续 TASK-20260725-014 只能在此基础上补齐备份门禁、维护模式和整个平台升级能力，不得创建同职责平行脚本。

### 输入与固定约定

- 仅接受一个符合 `mq-v[1-6]` 或项目正式版本白名单的参数；拒绝空值、`latest`、`dev` 和任意 shell 字符。
- Compose 文件默认 `docker-compose.hub.yml`，项目名默认 `ylcloud`，可从受控环境变量覆盖。
- 同一版本同时设置 app/frontend 的 `YLCLOUD_IMAGE_TAG`。
- 日志：`/var/log/ylcloud-deploy/<version>-<UTC时间>.log`。
- 当前版本：`/var/lib/ylcloud-deploy/current-version`，必须使用临时文件+原子 rename 写入。
- 锁：`flock /var/lock/ylcloud-deploy.lock`，并发运行立即失败。
- 用 `set -Eeuo pipefail`，设置 `ERR/INT/TERM` trap；日志不得输出 secret。

### 执行顺序

1. **互斥与预检**
   - 验证用户权限、版本、Docker daemon、Compose v2、磁盘空间、env/secret 文件、Compose 文件。
   - 执行 `docker compose ... config -q`。
   - 记录旧版本、旧 app/frontend 容器 ID、镜像 ID/digest、健康状态和 restart count。
   - 如果无法得到可回滚的旧镜像 ID，发布前失败。
2. **定向拉取**
   - 导出目标 `YLCLOUD_IMAGE_TAG`，只拉 `app frontend`；首装 `mq-v1` 时额外拉 RabbitMQ。
   - RabbitMQ 已存在时不随应用版本任意升级。
   - 校验拉取后的镜像存在且标签解析成功。
3. **基础设施**
   - 首次执行 `mq-v1` 时先 `up -d rabbitmq`，等待容器 health。
   - MySQL、MinIO、Qdrant 等现有基础设施只做状态检查，脚本不自动重建/升级。
4. **后端先行**
   - `docker compose up -d --no-deps --wait --wait-timeout <配置值> app`。
   - 验证容器 ID 或镜像 ID确实切换；目标与旧镜像不同时，容器未重建即失败。
   - 验证 health、restart count 未增长、公共设置/Actuator 探针、数据库迁移状态和 Rabbit 连接。
5. **后端冒烟**
   - 未登录公共接口。
   - 可配置的登录/鉴权探针。
   - 统一任务列表查询。
   - 创建并等待 `ASYNC_DEMO` 成功，确认 Outbox `SENT`、Inbox/Attempt 有记录；生产可使用受保护的运维 smoke endpoint，结果必须自动清理或标记。
6. **前端更新**
   - 后端通过后执行 `up -d --no-deps --wait --wait-timeout ... frontend`。
   - 验证镜像/容器切换、health、首页静态资源和前端反向代理到后端。
7. **完成**
   - 再执行一次整体 `docker compose ps` 和关键容器 restart count 对比。
   - 原子写当前版本；输出版本、镜像 digest、耗时、日志路径和成功状态。

### 异常自动回滚

任一步骤失败时 trap 只回滚本次已变更的 app/frontend：

1. 用预检时记录的旧镜像 ID重新标记临时回滚 tag，或恢复旧版本 tag。
2. 后端先恢复并等待健康，再恢复前端。
3. 执行与发布相同的基础 HTTP 和任务列表冒烟；回滚本身失败必须以不同退出码和醒目日志结束。
4. 不修改 RabbitMQ/MySQL 卷，不执行 Flyway undo/覆盖，不恢复数据库备份。
5. 保留失败目标镜像、容器日志和 `docker compose ps` 诊断，便于排查。
6. 只有目标版本全部验证成功才更新 `current-version`。

脚本明确禁止：`docker compose down -v`、删除 volume、`git pull`、构建生产镜像、自动清理镜像、把 secret 打入日志、修改已执行迁移。ShellCheck 必须通过，并用测试 Compose 演练成功、后端失败、前端失败、冒烟失败、回滚失败和信号中断。

## 不包含

- 迁移 Cleanup、Memory、Chat、Pipeline、RAG 的实际执行入口。
- RabbitMQ 集群、quorum queue 和公网 Management。
- 删除旧 `@Async`、领域任务表或旧 API。

## 验收标准

1. RabbitMQ 停止时创建示范任务，业务请求成功且任务为 `PENDING_PUBLISH`；恢复后自动成功。
2. 重复发送相同消息不会产生第二次有效执行。
3. Worker 崩溃、租约到期、自动重试到第 4 次、人工重试版本递增均符合 ADR。
4. 运行任务取消后显示 `CANCELED`，旧 Worker 不能晚写成功。
5. 新旧任务可分页查看，失败/Retry 原因可展开。
6. `deploy.sh` 全部正反向场景演练通过。

## 风险与回滚

- 新表/列保留；关闭 `async.mq.enabled` 即不创建新模式任务。
- Rabbit 宕机不回滚业务事务；依赖 Outbox 恢复。
- 部署脚本误操作风险由版本白名单、预检、锁和禁用危险命令控制。
