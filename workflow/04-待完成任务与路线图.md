# 待完成任务与路线图

## 当前优先级判断

当前项目已经具备可演示、可测试、可写简历的基础。后续不建议直接跳到复杂 Level 3，而应该先补齐 Level 2A 的执行安全与输入统一能力。

推荐路线：

```text
Level 2A：统一输入格式 + 执行安全增强 + 示例库
  ↓
Level 2B 增强：LLM Selector / 更多模板
  ↓
Level 3：AI Goal -> Workflow
```

## Level 2B：模板选择增强

当前规则选择版本已完成。

后续增强：

- 增加 LLMTemplateSelector。
- 保持 TemplateSelector 协议不变。
- 增加更多模板。
- 增加更丰富的 metadata 检索策略。
- 支持模板版本、标签和适用场景。
- 支持模板选择结果的置信度或拒绝原因。

注意：

LLM Selector 不应该直接执行自然语言输出。它应该输出结构化选择结果，然后仍然经过模板目录约束和 WorkflowValidator。

## Markdown Workflow Importer

当前状态：待设计。

目标：

```text
支持用户用约定好的 Markdown 格式描述 Workflow，再由 Importer 转换为标准 Workflow 数据结构。
```

待明确：

- Markdown 使用标题结构、表格结构还是 fenced code block。
- 如何声明 version、name、inputs、outputs。
- 如何声明 node id、type、prompt、tool、input、output、next。
- 如何处理 condition、loop、retry。
- 是确定性解析，还是交给 LLM 转换为 JSON / YAML。

当前建议：

先实现 fenced code block 版本，也就是从 Markdown 中提取 `yaml` 或 `json` 代码块，再走现有 WorkflowLoader 和 Validator。

## Loop Node 执行机制

当前状态：模型和基础引用校验存在，Executor 暂未执行 Loop。

后续需要设计：

- items 支持哪些类型。
- item 写入 Context 的变量名。
- loop body 按 body 列表执行，还是继续依赖 next。
- 是否允许嵌套 loop。
- 每轮输出是覆盖还是 append。
- 单轮失败后是终止、跳过还是继续。
- Trace 如何展示每一轮执行。
- 如何配合 max_steps 防止异常循环。

候选语义：

```text
LoopNode
  ↓
解析 items
  ↓
for item in items:
  context[item_var] = item
  执行 body 节点链
  ↓
全部完成后进入 next
```

## Context Store / Artifact Store

当前 Trace 不保存完整 Context，只记录 keys 和 diff。

后续可以做：

- MemoryContextStore。
- FileContextStore。
- run_id 隔离每次运行。
- 大对象按 key 保存到硬盘。
- Trace 只记录 context_refs。
- 大对象保存前脱敏。

这个方向适合后续做 UI 或长期运行记录。

## Level 3：AI 根据 Goal 生成 Workflow

目标：

```text
用户只提供 Goal，AI 生成 Workflow，系统校验 Workflow，然后执行。
```

待完成：

- WorkflowGenerator。
- 结构化输出约束。
- 生成结果保存。
- Validator 校验。
- 工具白名单和风险检查。
- 校验失败后的 self-repair。
- 只允许校验通过的 Workflow 执行。

关键原则：

AI 可以生成计划，但不能绕过 Validator、ToolRegistry 和安全检查。
