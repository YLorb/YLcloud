# 前端应用架构与页面功能

## 产品目标

前端把网盘、团队协作、知识库和 AI 助手组织为连续工作流，而不是暴露后端表结构。用户应在相同导航中理解文件在哪里、是否已索引、画像是否开启、任务是否失败以及如何重试。

## 技术结构

- main.tsx：React 启动。
- App.tsx：应用壳、主导航、全局页面选择与认证态。
- api.ts：统一 HTTP、JWT、业务响应和错误处理。
- appTypes.ts/types.ts：跨功能数据契约。
- styles.css：全局视觉与响应式规则。
- features：按用户任务组织页面和组件。

## 功能目录

| 目录 | 页面能力 |
|---|---|
| auth | 注册与登录 |
| files | 个人网盘、目录、上传、分片、移动复制和回收站 |
| spaces | Space、成员、文件、版本和导入 |
| knowledge-base | RAG 文档、任务、查询、配置和分析 |
| knowledge | 画像、Facet、质量、审核、版本 |
| assistant/chat | 多知识库会话、线程、输入与引用 |
| async | 统一后台任务 |
| settings | 个人/管理设置 |
| share | 匿名公开分享 |

## 关键实现

DriveApp.tsx 管理文件网格/列表、面包屑和上传；multipartUpload.ts 与 fileHash.worker.ts 负责断点续传；KnowledgeBaseView/KnowledgeSettingsView 分开运营和配置；KnowledgeOpsView 管理画像；AssistantSidebar/Thread/Composer 组成会话界面。

## 状态设计

服务端持久状态是权威，前端轮询或刷新恢复。通知不是成功判断来源：接口提交任务只表示已接受，最终需读取 task/document 状态。错误卡片保留明确中文原因和重试入口，未知错误不伪装成业务空状态。

## 权限与体验

按钮按角色隐藏或禁用，但安全由后端保证。目录支持双击/Enter、面包屑和返回上级；侧栏独立滚动，存储卡片固定；主要状态使用一致语义色。

## 当前验收边界

主要页面已通过构建和真实 Edge 路径验证；仍需建立可重复浏览器 E2E，覆盖刷新、重新登录、跨设备会话、移动端、物理触控板和常见缩放比例。
