## Level 3A：根据 Goal 生成并执行 Workflow

已完成：

- `WorkflowGenerator`：根据用户 Goal 调用 LLM 生成 Workflow YAML，包含自修复循环（校验失败时将错误信息注入修复 Prompt 重试一次）。
- `WorkflowCorrector`：接受已有 Workflow 文本与错误信息，利用 LLM 进行定向修正。
- CLI `make` 命令：仅生成并展示 Workflow YAML，不执行。
- CLI `make-and-run` 命令：生成 → 校验 → 向用户展示流程预览（`start -> plan -> ... -> end`）与 YAML → 询问确认 → 保存文件并执行。
- CLI `correct` 命令：加载现有 Workflow 文件，根据 `--error` 信息调用 LLM 修正并输出结果。
- 用户确认机制：使用 `typer.confirm` 在 CLI 中询问，支持 `--yes` 跳过确认（供测试与自动化使用）。
- `tests/test_cli.py` 新增 `FixedLLM` 测试替身与两条 `make-and-run` 测试（确认执行 / 拒绝不保存）。

## CLI 能力

已完成命令：

- `run`：执行人工定义 Workflow（支持 `.json / .yaml / .yml / .md`）。
- `select`：根据 Goal 从模板库选择 Workflow 并执行。
- `make`：根据 Goal 由 LLM 生成 Workflow YAML，仅展示不执行。
- `make-and-run`：生成 Workflow，向用户展示流程预览与 YAML，确认后保存并执行。
- `correct`：加载现有 Workflow，根据错误信息调用 LLM 修正。

支持参数：

- `--provider mock|deepseek`
- `--model`
- `--templates`
- `--trace / --no-trace`
- `--selector rule|llm|hybrid`
- `--yes`（跳过 `make-and-run` 确认，供测试与自动化使用）
- `--output / -o`（指定生成或修正后的 Workflow 保存路径）
- `--error`（`correct` 命令的错误信息参数）

CLI 使用 Typer 实现命令解析，使用 Rich 输出结果。
