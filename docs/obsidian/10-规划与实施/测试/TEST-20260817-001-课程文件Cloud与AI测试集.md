## 8. 评分规则

### 8.1 Cloud

- P0 用例必须 100% 通过；P1 通过率不低于 95%。
- 上传完成后的源文件与下载文件 SHA-256 必须一致。
- 不允许孤儿对象、重复逻辑记录、错误配额、跨用户秒传越权或永久卡住的异步任务。

### 8.2 RAG

- 主样本解析成功率 100%；明确不支持的格式必须真实失败或跳过，不能伪 READY。
- R06-R09 的相关源应进入 Top 5；P0 精确问题的支持片段应进入最终上下文。
- 引用文件、Space、逻辑文件 ID、页码/片段位置可追溯，访问时重新授权。
- 删除、权限撤销和重建后的 MySQL、MinIO、Qdrant 派生状态一致。

### 8.3 AI 问答

- Q01-Q16 必含事实点准确率不低于 95%，且每题至少有一个真实支持引用。
- Q17-Q18、Q22 在无依据时 no-answer 正确率 100%，citations/contexts/hitChunkIds 为空。
- Q19-Q20 的安全与权限负例必须 100% 通过。
- 不以文风相似度评分；重点检查事实完整性、引用支持性、权限和是否产生幻觉。

## 9. 建议执行顺序

1. 记录环境版本、配置、Space/账号和源文件清单摘要。
2. 先执行 C01-C16，验证文件节点、摘要、权限和基础可恢复性。
3. 等待主样本索引完成，执行 R01-R14 并记录任务 ID、parser、chunk/point 数量。
4. 新建 AI Assistant 会话，执行 Q01-Q22；每题保存问题、答案、引用快照、响应状态和截图。
5. 执行删除、成员撤销、故障和重建，再复测受影响问题。
6. 清理本轮创建的数据，确认源目录未变化，并生成独立测试记录。

## 10. 证据与记录模板

每条用例至少记录：

- 执行时间、执行人、版本/commit、浏览器与 Compose 服务版本；
- 源文件绝对路径、大小、SHA-256，云端 userFileId/spaceFileId/fileId；
- uploadId、异步 taskId、RAG documentId、parser/version、chunk 数、Qdrant point 数；
- 实际答案、noAnswer、citations、contexts、hitChunkIds；
- API 响应、关键日志、数据库只读查询、截图或报告路径；
- 预期、实际、PASS/FAIL/BLOCKED、缺陷编号与残留风险。

不得把访问令牌、密码、Secret、MinIO 签名 URL 或完整内部提示词写入测试证据。
