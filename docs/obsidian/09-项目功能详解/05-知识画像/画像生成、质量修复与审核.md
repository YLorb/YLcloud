# 画像生成、质量修复与审核

## 产品目标

模型生成的画像便于浏览和治理，但模型输出可能缺字段、格式错误、分类不稳定或内容无依据。系统必须把生成、校验、修复和人工审核分开，不能把一次 LLM 返回直接当作权威资产。

## 生成流程

KnowledgePipelineService 从 RAG_READY 文档读取有效 chunk，buildContext 在 MAX_CONTEXT_CHARS 范围构造上下文，并要求 RagModelClient 生成结构化画像。期望字段包括摘要、分类、标签、关键词、候选问题等。

KnowledgeProfileParser 从模型文本提取 JSON；KnowledgeProfileNormalizer 清理空白、去重、限制数量并标准化分类；KnowledgeProfileValidator 校验 schema 和关键字段；KnowledgeProfileQualityService 计算问题列表和质量结果；KnowledgeProfileRepairService 对可安全修复的问题自动补正。

~~~mermaid
flowchart LR
  C[有效 RAG chunks] --> G[LLM 生成]
  G --> P[JSON 解析]
  P --> N[标准化]
  N --> V[Schema/内容校验]
  V --> Q[质量评分]
  Q -->|可修复| R[自动修复再校验]
  Q -->|需人工| H[NEEDS_REVIEW]
  R --> W[事务写画像、问题、版本、审计]
  V -->|合格| W
~~~

## 质量与状态

PROFILE_VALID 表示结构和内容满足规则；PROFILE_NEEDS_REVIEW 表示结果可保存但需要人工判断；PROFILE_FAILED/INVALID 表示本次不能成为有效资产。质量分数是辅助信号，不能替代具体 QualityIssue。

## 资产操作

KnowledgeProfileAssetService 和 KnowledgeProfileWriteService 支持：

- 查看/编辑画像；
- 自动或人工分类；
- 审核通过/拒绝；
- 重新生成、重新分类；
- 版本列表、差异和恢复；
- 写 space_knowledge_audit_log。

## 事务边界

当前画像、问题、版本和审计应在本地事务一致提交。画像事务与 RAG SUCCESS/ACTIVE 完全解耦：画像回滚只能让画像任务失败，不能撤销有效向量索引。

## 设计原因与演进

LLM 输出经过显式解析和质量门槛，可提高可解释性。当前 APPROVED/NEEDS_REVIEW 已形成治理基础；更成熟的发布模型应进一步拆分 CANDIDATE 与 PUBLISHED，让人工批准成为正式线上资产切换。
