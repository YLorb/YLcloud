## 正确性审查

- 受理事务任一 INSERT 失败会 rollback；唯一键竞争 rollback 后读取既有幂等记录并校验 request hash。
- 领取使用行锁与 `SKIP LOCKED`；状态推进同时要求 run version 和 from-status 匹配，失败者不覆盖胜者。
- Run 与当前 Execution 的 claim/CAS/cancel 位于同一数据库事务，避免展示状态与执行状态分裂。
- 服务状态接口不返回持久化的 question、短期 Context 或 permission scope。
- migration 仅向前；不自动 down，升级回滚依赖升级前备份。

## 安全审查

- Workflow 数据只落独立 Schema；运行账号无业务 Schema 和全局权限，Secret 只通过环境/部署 Secret 注入。
- SQL 值全部使用参数绑定；唯一动态标识符仅存在于测试代码的固定白名单/专用测试库。
- HTTP 500 保持固定脱敏响应；数据库连接信息、SQL 和用户正文不回显。
- 临时结果只有契约 hash 匹配才删除；TTL 清理只作用于 Workflow 临时结果和过期幂等记录。
