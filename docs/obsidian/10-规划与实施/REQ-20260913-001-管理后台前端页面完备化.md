# 管理后台前端页面完备化

## 1. 背景与目标

`/admin` 已建立独立布局和 14 个侧栏入口，但当前实现主要停留在路由、静态表头和占位内容：`nodes`、`orders`、`events`、`reports`、`oauth` 仍直接渲染 `PlaceholderPage`，面板首页使用 `--` 与图表占位，用户组、用户、文件、分享和任务页面仅有空表格，参数设置与文件系统仍包含“敬请期待”。现有前端也没有覆盖管理后台页面的专项测试。

本需求先完成管理后台全部页面的前端结构和交互原型，使每个入口都具备可评审、可测试、可替换数据源的完整页面。当前阶段不建设后端能力，不把模拟操作描述为真实系统操作。

下游方案见 [[10-规划与实施/ADR-20260913-001-管理后台前端原型与Mock数据架构]]。

## 2. 用户、场景与业务价值

- 用户：部署所有者和具备管理入口权限的管理员。
- 主场景：进入管理后台、浏览 14 个业务入口、切换标签、组合筛选、查看空状态、打开详情/表单/确认弹窗并体验临时操作反馈。
- 失败场景：Mock 查询失败、表单校验失败、危险操作取消、无数据、窄屏表格溢出和无权限访问。
- 价值：先稳定信息架构、页面密度、交互规范和领域边界，降低后续逐页接入真实 API 时的返工量。

## 3. 需求范围

### 3.1 页面范围

| 路由 | 页面 | 必须具备的前端结构 |
|---|---|---|
| `/admin/dashboard` | 面板首页 | 时间范围、核心指标、趋势区域、系统状态、最近活动、快捷入口 |
| `/admin/settings` | 参数设置 | 站点、会话、验证码、增值服务、邮件、任务队列、服务器与系统维护标签；中宽表单、脏状态、保存/放弃确认 |
| `/admin/fs` | 文件系统 | 参数、全文搜索、文件图标、在线浏览应用标签；搜索条件、结果表/卡片、配置表单和空状态 |
| `/admin/storage` | 存储策略 | 策略列表、筛选、创建/编辑抽屉、启停确认；备份概览、历史和恢复校验标签 |
| `/admin/nodes` | 节点 | 节点概览、状态筛选、负载/容量列、节点详情、启停/维护原型 |
| `/admin/user-groups` | 用户组 | 搜索、分页、组列表、权限摘要、配额摘要、创建/编辑/删除弹窗 |
| `/admin/user-list` | 用户 | 搜索、角色/状态/用户组筛选、分页、创建/编辑、状态变更、权限详情 |
| `/admin/file-list` | 文件 | 文件名/UUID/所有者/类型筛选、分页、文件详情、导入与删除确认原型 |
| `/admin/shares` | 分享 | 分享 ID/文件/分享人/状态筛选、分页、详情和撤销确认 |
| `/admin/tasks` | 后台任务 | 类型/状态/创建者/节点筛选、分页、详情时间线、重试/取消/清理原型 |
| `/admin/orders` | 订单 | 订单号/用户/类型/状态/时间筛选、金额摘要、详情和状态操作原型 |
| `/admin/events` | 事件 | 系统事件与安全审计标签、级别/类型/主体/时间筛选、详情、审计留存设置原型 |
| `/admin/reports` | 滥用举报 | 状态/类型/优先级筛选、证据摘要、详情、分派和处置原型 |
| `/admin/oauth` | OAuth 应用 | 应用列表、状态/所有者筛选、创建/编辑、Scope、回调地址和 Secret 一次性展示原型 |

### 3.2 信息架构决策

- 参数设置、文件系统、存储策略保留为三个独立侧栏页面，不互相复制同一表单。
- 安全审计并入“事件”的独立标签。
- 备份状态、备份历史和恢复校验并入“存储策略”的独立标签。
- 系统维护并入“参数设置”的“服务器与维护”标签。
- 保持当前 14 个路由和侧栏顺序，管理员从主应用进入 `/admin`，返回时回到 `/files`。

### 3.3 Mock 与交互规则

- 本阶段所有管理页面统一使用前端 Mock 数据源，不依赖后端请求。
- 默认列表为空，但标题、统计、筛选、表头、分页、操作区、空状态和详情容器必须完整呈现。
- 新增、编辑、删除、启停、重试等操作只修改当前页面内存状态，刷新页面后重置。
- 页面顶部持续显示“演示模式 / 操作不会保存到服务器”，成功提示必须使用“已在演示数据中更新”等准确措辞。
- 不使用 `localStorage`、IndexedDB 或 Cookie 保存模拟业务数据。

## 4. 非目标

- 新增或修改 Java Controller、Service、Mapper、数据库迁移、消息队列、Qdrant 或对象存储逻辑。
- 将模拟操作写入生产数据，或宣称节点、支付、举报、OAuth 等后端能力已完成。
- 定义真实订单、支付、节点调度、举报处置或 OAuth 协议的最终业务契约。
- 在本阶段删除现有真实 API、旧管理组件或后端实现。
- 引入新的重量级 UI 框架，或借此次改造重写普通用户页面。

## 5. 验收标准

1. 14 个路由均由专属页面组件承载，不再路由到 `PlaceholderPage`，页面正文不出现“敬请期待”。
2. 每页至少具备页面标题、作用说明、演示模式提示、主要操作、筛选/标签、数据承载区、空状态和分页或明确的“不适用”说明。
3. 每个创建/编辑入口能打开结构完整且可校验的表单；危险操作必须二次确认；提交只更新内存并准确提示未持久化。
4. 参数设置、文件系统、存储策略保持独立；审计、备份、维护按本需求指定位置归并。
5. 默认 Mock 数据为空，页面仍可完整评审；测试可注入确定性 fixture 验证有数据、错误和操作状态。
6. 页面遵循蓝白灰、低阴影、圆润边框、清晰选中态和工具型效率的 Cloudreve 风格；复用当前设计 Token 和 UI 组件。
7. 320、768、1024、1440 像素宽度下无主操作不可达、正文覆盖或不可恢复的横向溢出；数据表允许容器内横向滚动。
8. 浅色/深色主题、键盘焦点、可访问名称、弹窗焦点管理和 reduced-motion 均可用。
9. 未授权用户不能通过前端路由进入管理页；Mock 数据不得包含真实账号、密钥、Token 或个人数据。
10. 后续实现必须通过前端单元/组件测试、路由回归、异常与安全测试、生产构建及浏览器 E2E，并生成独立测试记录。

## 6. 约束、假设与风险接受

- 约束：沿用 React、React Router、TanStack Query/Table、Radix UI、Lucide、Vitest 和现有 CSS Token；本阶段不新增依赖。
- 假设：页面字段用于确认信息架构，不构成未来后端契约；接入 API 时允许根据真实 DTO 调整字段。
- 已接受风险：页面操作不持久化。通过常驻演示标识、精确 Toast 和无本地持久化降低误解风险。
- 已接受风险：Mock 阶段不能验证真实权限、事务、审计和数据正确性；这些能力必须在后续 API 接入任务中重新验收。
- 未决事项：无。页面范围、数据方式、交互级别、设置页结构及旧管理能力归并位置已于 2026-09-13 由用户确认。
