# mq-v3：用户记忆任务迁移

## 目标

将用户记忆提取、画像派生和记忆向量索引迁入 memory 队列，保证同一用户/会话资源的版本顺序和取消后旧结果不可回写。

## 依赖与输入

- TASK-20260725-017 已通过观察。
- `UserMemoryExtractionService`、`UserMemoryService` 及相关 mapper/vector 实现。

## 修改范围与产物

- 定义 `MEMORY_EXTRACT`、`MEMORY_PROFILE_BUILD`、`MEMORY_VECTOR_INDEX` 等任务类型。
- 业务提交记忆原始数据时，同事务创建 task/outbox；消息只带 ID。
- 使用 `user-memory:{userId}:{sourceId}` 形式稳定资源键和单调版本。
- 把 `@Async`/直接 executor 调用改为 Feature Flag 双路径；消费者调用同步核心函数。
- 模型/向量调用使用可重试错误分类；权限丢失、来源删除、内容非法为 fatal/stale。
- 详情错误信息不得泄露对话正文、模型请求或密钥。
- memory 默认并发 2、prefetch 1。

## 不包含

- 改变记忆抽取算法、Prompt 或画像产品规则。
- Chat/Workflow 消息迁移。

## 验收标准

1. 相同业务事件重复提交只产生一个有效任务。
2. 用户删除/更新后，旧版本抽取或向量结果为 `SKIPPED_STALE`。
3. 模型临时失败按 1 分钟重试，最多 4 次；fatal 不自动重试。
4. 取消运行任务后，模型返回结果不能落成有效画像。
5. Flag 关闭可回到旧路径，不发生 MQ 和 `@Async` 双执行。

## 测试与通过

- 并发更新、重复消息、模型超时/限流、Qdrant 不可用、取消和租约过期。
- 断言敏感内容不进入消息、任务错误摘要和普通日志。
- 满足 TEST-20260725-002 通用门禁和 `mq-v3` 场景。

## 风险与回滚

- 外部模型调用已发生但结果未提交时可能重复计费；使用 provider request key（如可用）并记录调用结果键。
- 回滚仅关闭 `async.mq.memory` 并部署旧镜像，新增表不删除。
