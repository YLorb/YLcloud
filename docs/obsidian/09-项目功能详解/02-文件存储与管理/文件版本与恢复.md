# 文件版本与恢复

## 产品目标

Space 文件可保留历史内容、查看版本并恢复。恢复不是把历史记录偷偷改成当前值，而是产生新的可审计当前版本；恢复为副本则创建独立文件节点和版本链。

## 数据与流程

file_version 保存 spaceFileId、versionNo、当时物理 fileId/摘要、文件名、创建者和时间。InitialFileVersionService 在 Space 初次上传、导入或启用版本功能时幂等补建 v1，解决“第一次更新后没有原始版本”的问题。

上传新内容时，FileVersionService 在切换当前物理引用前保存版本记录。restore 读取目标版本，创建新的当前版本语义并触发 RAG 重建，使向量与恢复后的正文一致。

## 两种恢复

- 原位恢复：同一个 space_file 指向恢复内容，同时新增版本记录，历史不被覆盖。
- 恢复为副本：创建独立 MinIO 对象、file_info、space_file 和 v1 版本链；名称按 “-副本(n)” 递增。

即使当前记录与目标版本的名称、hash、MD5、大小完全相同，副本恢复也不能直接返回已有版本，否则用户得到的不是独立文件。

## 核心代码

- SpaceFileController：版本开关、版本列表、恢复入口。
- FileVersionService：版本写入、查询、恢复和副本命名。
- InitialFileVersionService：v1 幂等初始化。
- SpaceFileService：当前文件引用变更与 RAG 联动。
- FileVersionMapper、file_version。
- MinioclientUtil：独立对象复制/读取。

## 一致性

版本表、当前 space_file 引用和必要元数据在 MySQL 事务中提交；MinIO 复制失败不能切换当前版本。恢复成功后 RAG 作为派生索引异步重建，期间旧索引不得伪装为新正文索引。

## 设计权衡

不可变版本记录比直接覆盖可靠，代价是物理引用和清理更复杂。物理文件清理必须把 file_version 计入引用，确保历史版本仍可下载和恢复。
