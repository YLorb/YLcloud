# 节点与后台任务页面

## 目标与需求覆盖

完成 `/admin/nodes` 与 `/admin/tasks` 的运维型前端原型，建立一致的状态、筛选、详情和危险操作体验。

## 前置依赖与输入

- 前置：TASK-20260913-001。
- 输入：现有 AdminTasksPage、普通用户 TasksPage、统一任务状态文档和 AdminLayout。
- 下游测试：[[10-规划与实施/测试/TEST-20260913-001-管理后台前端页面验收要求]]。

## 修改范围与预期产物

1. 节点页提供总数/在线/异常/维护指标、状态筛选、节点表、负载/容量摘要、详情和启停/维护确认。
2. 任务页提供类型/状态/创建者/处理节点/时间筛选、分页、状态徽标、详情时间线和重试/取消/清理确认。
3. 两页共享运维状态视觉，但模型和操作保持领域独立。
4. 空数据、未知状态、超长错误、无处理节点和失败命令均有明确呈现。

## 明确不包含

- 节点注册、心跳、调度、真实任务查询、重试、取消、清理和队列操作。

## 验收标准

- `/admin/nodes` 不再使用 PlaceholderPage；两页均具备完整表头、筛选、详情和操作结构。
- 危险操作不能一键完成，模拟成功/失败准确说明没有服务器副作用。
- 任务详情时间线和节点详情在窄屏可访问，关闭后焦点恢复。

## 测试、风险与回滚

- 测试：空/有数据、组合筛选、状态映射、详情、时间线、重复提交、危险确认、Mock 失败和键盘操作。
- 风险：节点与任务状态可能和后续后端契约不同；枚举必须提供 unknown fallback。
- 回滚：节点路由恢复占位、任务页恢复旧实现；不影响真实任务 API。
- 实现 Agent/LLM 必须生成完整测试用例和独立测试记录，并回写状态与证据。
