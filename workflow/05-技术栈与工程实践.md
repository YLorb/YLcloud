# 技术栈与工程实践

## 技术栈总览

项目主要技术栈：

- Python 3.10+
- Pydantic
- PyYAML
- Jinja2
- Typer
- Rich
- pytest
- OpenAI Python SDK
- DeepSeek OpenAI 兼容 API
- python-dotenv
- JSON Schema
- Git

## 为什么使用 Python

Python 适合快速实现 Agent 原型：

- 数据结构表达简单。
- CLI、测试和文件处理成熟。
- LLM API 生态完善。
- 很适合做 Workflow Engine、Tool Calling 和 Mock 测试。

## 配置与模型

### JSON / YAML

Workflow 支持 JSON 和 YAML。

JSON 更适合机器生成与严格校验；YAML 更适合人工编写和阅读。

### Pydantic

Pydantic 用于定义：

- Workflow。
- RetryPolicy。
- 各类 Node。
- TemplateMetadata。
- TemplateSelection。
- Level2RunResult。

它承担基础结构校验，并让后续代码可以面向明确类型开发。

### JSON Schema

`schemas/workflow.schema.json` 用于描述固定 Workflow JSON 格式。

它适合：

- 给用户看固定配置结构。
- 给编辑器或后续生成器做格式约束。
- 作为 Workflow IR 的外部契约。

## 模板与变量解析

项目目前实现了自己的轻量 VariableResolver，只支持：

```text
{{ variable }}
```

虽然依赖里有 Jinja2，但当前没有开放 Jinja2 的表达式、循环、过滤器和函数调用能力。

这样做更安全，也更适合 Level 1：

- 不执行表达式。
- 不支持函数调用。
- 不访问属性链。
- 缺失变量显式失败。
- 完整变量引用保留原始类型。

## CLI

CLI 使用：

- Typer：定义命令和参数。
- Rich：展示结果、表格和错误信息。

当前命令：

- `run`
- `select`

CLI 的价值：

- 方便 Demo。
- 方便测试。
- 方便面试展示。
- 让项目不是只停留在库代码。

## LLM 抽象

项目使用 `LLMClient` Protocol，而不是让 Executor 直接依赖某个厂商 SDK。

当前实现：

- MockLLM。
- DeepSeekLLM。

好处：

- 测试时使用 MockLLM，稳定、快速、无费用。
- 真实运行时用 DeepSeekLLM。
- Executor 不需要知道底层模型厂商。

## Tool 抽象

ToolRegistry 保存：

```text
tool name -> callable
```

当前 ToolCallable 形态：

```text
Callable[[Any], Any]
```

这样可以先跑通工具调用链路。

后续需要升级为 ToolSpec：

- input_schema
- permission
- risk_level
- description
- timeout

这会让工具调用更接近真实 Agent 产品。

## 测试策略

项目测试以稳定、可复现为核心：

- MockLLM 让 LLM 节点可预测。
- mock_search 不联网。
- FakeMCPToolProvider 不连接真实 MCP Server。
- DeepSeek 客户端测试使用 Fake OpenAI Client。
- CLI 用 Typer CliRunner 测试。
- benchmark 使用固定 40 条自建标注意图。

这套策略保证：大部分测试不依赖网络、不依赖真实模型、不产生费用。

## 安全实践

当前已有安全边界：

- YAML 使用 safe_load。
- Validator 检查工具白名单。
- ToolRegistry 不允许 workflow 动态 import 任意函数。
- Selector 不使用 eval / exec。
- Condition 不执行表达式，只做 truthy 判断。
- Trace 对敏感字段脱敏。
- DeepSeek 错误信息脱敏。
- `.env.local` 加入 `.gitignore`。
- API Key 通过环境变量读取。

后续仍需增强：

- Tool input schema 校验。
- Tool 权限检查。
- Tool 风险等级。
- 节点超时和全局超时。
- 真实 MCP 工具权限控制。

## 工程实践

项目目前体现出的工程实践：

- Loader / Validator / Executor 职责分离。
- Planner / Executor 分层。
- Protocol 抽象 LLM。
- Registry 控制工具调用面。
- Pydantic 约束输入结构。
- Mock Provider 保证测试稳定。
- CLI 和库代码分离。
- 文档记录每次设计决策。
- 代码完成后做正确性和安全性双审查。
