# 统一异步任务视图

## 产品目标

用户不应到多个页面猜测后台是否仍在处理。统一任务视图聚合当前用户有权查看的 RAG 索引和知识画像任务，展示来源、类型、状态、进度和错误。

## 聚合范围

AsyncTaskController 的 /api/async 调用 AsyncTaskService，聚合：

- space_rag_task：文件索引、空间重建、删除和修复；
- space_knowledge_pipeline_task：单文档和空间画像批次。

普通上传、分片上传和当前同步分片合并不进入该列表，因为它们有独立的前端进度与恢复协议。聚合必须按当前用户和 Space 成员关系过滤。

## 统一模型

不同任务表被转换为共同 VO：

- id 与 source；
- taskType；
- PENDING/RUNNING/SUCCESS/FAILED/SKIPPED；
- total/success/failed/progress；
- target 文件或 Space；
- errorMessage、created/started/finished time。

状态同名不代表业务完全相同，UI 还要显示 source 和 stage。例如画像 SKIPPED 需要展示 PROFILE_DISABLED 或 NO_ELIGIBLE_DOCUMENTS。

## 前端

AsyncTasksView 轮询列表，使用语义色区分运行、成功、跳过和失败。终态通知应从服务端持久计数恢复，不依赖浏览器内存；这对画像“成功 X、失败 Y”尤其重要。

## 设计原因

采用查询聚合而不是立即创建通用任务总表，减少现有业务迁移成本；但若未来引入 MQ、统一重试和任务依赖图，可演进为公共 task registry。无论如何，业务原表仍应保留领域状态和不变量。

## 失败与权限

空任务返回空列表，不是 500。任务错误摘要脱敏并限长。用户退出 Space 后不能继续看到该 Space 的历史任务详情。
