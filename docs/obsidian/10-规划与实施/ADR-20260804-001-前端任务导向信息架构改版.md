# 前端任务导向信息架构改版方案

## 1. 背景与目标

当前前端已覆盖文件、空间、知识库、问答、记忆、任务及管理功能，但页面按后端领域实体组织，一级入口过多，主要流程被功能目录淹没。改版目标是在不改变后端业务能力的前提下，让首次用户能直接完成：

> 上传文件 → 查看处理状态 → 开始提问

登录后仍进入 `/files`，不新增独立工作台。

## 2. 用户、场景与业务价值

- 普通用户：上传个人或团队资料，并基于资料提问。
- 空间成员：在当前空间内查看文件、知识库和处理进度。
- 管理员：通过设置入口访问权限、审计、备份和运维能力。
- 业务价值：缩短首次成功路径，减少导航判断成本，提高资料完成索引并进入问答的转化率。

## 3. 需求范围与非目标

### 范围

- 一级导航压缩为：文件、知识库、智能问答、任务。
- 团队空间变成全局范围选择器；成员和空间配置由选择器的管理入口进入。
- 记忆管理、账号设置及管理员功能归入“设置”。
- `/files` 空状态改为三步任务引导，并根据实际数据展示进度。
- 统一颜色、字号、术语、按钮层级和页面容器规则。
- 重构智能问答的技术文案、会话侧栏和会话操作。
- 增强文档、引用和检索解释的视觉优先级。

### 非目标

- 不修改 RAG、Workflow、索引或消息队列后端流程。
- 不新增首页路由。
- 不删除既有能力或旧 URL。
- 本轮不重新设计管理员表单的业务逻辑。

## 4. 验收标准

1. 普通用户一级导航仅显示四个核心入口和一个设置入口。
2. 用户从空文件页最多一次主操作即可上传资料；上传后可明确看到处理状态和下一步。
3. 已完成索引的资料提供直接进入智能问答的操作。
4. 主要操作统一使用紫色；绿色不再用于普通 CTA。
5. 用户界面不出现 Java、持久化等实现术语；技术阶段默认折叠。
6. 普通说明和引用正文不低于 12px，主要正文为 13–14px；9px 字号清零。
7. 1366×768 下智能问答仅保留一层常驻侧栏，不产生页面与消息区双重滚动。
8. 会话删除功能在鼠标、键盘和触摸环境均可发现和操作。
9. `/files`、`/spaces`、`/knowledge`、`/assistant`、`/memories`、`/tasks` 和管理 URL 仍可直接访问。
10. 375px、768px、1024px、1366px 和 1440px 宽度无横向溢出，关键操作不被固定导航遮挡。

## 5. 现状分析、问题诊断与证据

- `AppShell.tsx` 将七个普通用户功能并列为一级导航，管理员再追加四个入口。
- `KnowledgePage.tsx` 在一级知识库入口下继续提供六个并列标签。
- `AssistantPage.tsx` 直接展示 “Workflow 正在准备上下文，Java 将生成最终回答”及后端持久化说明。
- `app.css` 中 `.assistant-page` 使用固定视口高度及 240px 会话栏；全局桌面侧栏同时常驻。
- `.session-item > button:last-child` 默认 `opacity: 0`，触摸设备缺少 hover 发现路径。
- 样式存在大量 9–11px 文本；输入区说明为 9px。
- `:root` 定义 `--confirm`，但任务成功、权限文本及 checkbox 使用未定义的 `--success`。
- 设计规范声明紫色是 Primary、绿色是 Success/Confirm，但业务页面将绿色用于新建会话、上传和发送等主操作，语义冲突。
- 文件、空间与知识库页面存在顶栏标题、上下文卡、标签卡和内容卡多层嵌套。

## 6. 约束、假设与未决事项

- 保留现有 React、React Router、TanStack Query、Radix、Lucide 和单体 CSS 技术栈。
- 假设现有 API 已能提供文件处理状态、知识库索引状态和空间列表；若缺少聚合数据，前端可并行现有查询，不新增阻塞式聚合接口。
- 保持旧 URL 可用，避免书签和外部链接失效。
- 未决事项：无。用户已选择继续以文件页作为登录落点。

## 7. 合理候选方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 新增任务型首页 | 汇总能力强 | 新增入口和维护面，再造一层导航 | 不采用 |
| 文件页承担任务入口 | 路径最短、复用现有路由、改造成本可控 | 文件页需兼顾浏览与引导 | 采用 |
| 仅换文案和颜色 | 成本最低 | 无法解决信息架构和双侧栏问题 | 不采用 |

## 8. 用户选定方案与架构决策

采用“文件页承担任务入口”。`/files` 同时是文件管理页和首次成功路径入口；有数据时回归高效文件管理，无数据或存在处理中资料时呈现任务引导。

## 9. 系统边界、模块职责与关键流程

### 全局壳层

- 一级导航：文件、知识库、智能问答、任务。
- 顶部空间选择器：个人文件或具体团队空间。
- 设置菜单：记忆、账号；管理员追加管理设置、安全审计、备份和运维。
- 页面不再重复展示无信息增量的标题和说明。

### 文件页状态

1. 无文件：突出“上传文件”，展示三步流程和可选示例资料。
2. 有文件正在处理：展示紧凑进度条和“查看任务”。
3. 已索引：展示“开始提问”，并携带当前空间/知识库上下文。
4. 处理失败：展示原因摘要、重试和任务详情入口。

### 知识库

- 默认保留“文档”和“知识探索”两个主要视图。
- 概览指标合并到页首摘要。
- 画像、处理任务、检索分析、配置进入“更多”或二级管理区。
- 强化文档预览、文档关联、引用片段和检索解释。

### 智能问答

- 会话列表改为可折叠抽屉；1366px 及以下默认收起。
- 全局导航与会话抽屉不得同时长期占据内容宽度。
- 用户状态文案为“正在检索相关文档并生成回答……”。
- 折叠的“处理详情”可显示查询改写、混合检索、重排序和生成回答。
- 会话操作使用常驻低对比度三点菜单，支持 focus-visible 与触摸操作。

## 10. 接口、数据模型与状态设计

- 后端 API 和持久化模型保持不变。
- 新增前端派生状态：`EMPTY`、`PROCESSING`、`READY`、`FAILED`。
- 派生状态只基于已有文件、任务和索引查询结果，不写回服务端。
- 空间选择器统一维护当前 scope，并同步到 URL 查询参数，确保刷新和分享后上下文可恢复。

## 11. 异常、边界、降级和恢复

- 文件状态与任务状态不一致时，优先显示可解释的保守状态，并提供刷新。
- 知识库为空时，推荐问题触发选择资料/知识库，而不是形成无反馈的禁用操作。
- 查询失败不阻断文件列表；任务引导区域独立降级。
- 会话抽屉状态仅影响布局，不影响会话持久化。

## 12. 安全、隐私与合规

- 不改变权限模型；空间选择器仅展示用户有权访问的范围。
- 设置入口的收纳不等于隐藏权限校验，路由和 API 仍需执行原有授权。
- 引用预览不得泄露当前空间范围之外的内容。

## 13. 性能、容量、可靠性与可观测性

- 复用 React Query 缓存，避免文件页引导重复请求相同资源。
- 会话抽屉按需加载历史记录，避免首屏阻塞。
- 为上传、处理状态跳转和进入问答记录前端事件，以便衡量流程完成率；不记录文档正文或提问内容。

## 14. 兼容、迁移、发布与回滚

- 路由采用兼容迁移：旧 `/spaces` 可重定向至带空间 scope 的 `/files`，原页面暂保留一个版本周期。
- `/memories` 与管理路由继续可直达，只从一级导航移除。
- 通过前端特性开关分批发布新导航和新文件页。
- 回滚只需关闭特性开关并恢复旧 AppShell；不涉及数据回滚。

## 15. 原子实施任务及依赖顺序

### TASK-20260804-001：修复设计令牌和基础排版

- 依赖：无。
- 修改：统一 `--primary`、`--confirm`、`--info`、`--danger`；将未定义 `--success` 替换为 `--confirm`；清理 9px，建立 12/13/14px 辅助与正文层级。
- 不包含：页面结构调整。
- 验收：语义色用例通过；全局不存在未定义颜色变量；关键正文满足字号标准。
- 回滚：单独回退 token 与排版提交。

### TASK-20260804-002：重构全局导航与空间选择器

- 依赖：TASK-20260804-001。
- 修改：压缩一级导航；新增全局 scope 选择器；将记忆、账号和管理功能归入设置菜单；保留旧路由。
- 不包含：文件页流程引导。
- 验收：普通用户只见四个核心入口；管理员功能可从设置到达；键盘和移动端导航可用。
- 回滚：恢复原 navItems 和移动导航。

### TASK-20260804-003：重构文件页核心闭环

- 依赖：TASK-20260804-002。
- 修改：按 EMPTY/PROCESSING/READY/FAILED 呈现三步引导、主 CTA 和状态跳转；减少分类栏及内容卡套娃。
- 不包含：修改上传与处理后端。
- 验收：四种状态都有唯一明确主操作；上传后能到任务，索引后能到问答。
- 回滚：通过特性开关恢复原文件页。

### TASK-20260804-004：简化知识库信息架构

- 依赖：TASK-20260804-002。
- 修改：主要视图聚焦文档和知识探索；其余能力进入二级管理；移除重复容器，强化预览、引用和检索解释。
- 不包含：修改知识画像算法。
- 验收：核心视图不超过三个直接可见标签；知识内容的视觉优先级高于指标卡。
- 回滚：恢复旧标签布局。

### TASK-20260804-005：重构智能问答布局与内容

- 依赖：TASK-20260804-001、TASK-20260804-002。
- 修改：会话抽屉、三点菜单、用户化状态文案、折叠处理详情、知识库未选择时的引导。
- 不包含：修改回答生成流程。
- 验收：1366×768 无双滚动；触摸和键盘可删除会话；主界面无 Java、Workflow、持久化术语。
- 回滚：恢复旧 Assistant 布局组件。

### TASK-20260804-006：统一内容设计与登录文案

- 依赖：TASK-20260804-002。
- 修改：建立中英文使用规则；将 AI Assistant 改为“智能问答”，Admin Settings 改为“管理设置”；优化登录卖点和注册概念。
- 不包含：品牌命名变更。
- 验收：主导航和用户提示使用中文；技术术语仅出现在高级详情；注册文案与实际行为一致。
- 回滚：恢复原文案资源。

### TASK-20260804-007：响应式、无障碍与回归收口

- 依赖：TASK-20260804-003 至 TASK-20260804-006。
- 修改：断点、焦点、触摸目标、滚动容器、深色主题和视觉回归修正。
- 不包含：新增业务能力。
- 验收：满足第 4 节全部标准。
- 回滚：逐项回退响应式覆盖规则。

## 16. 测试范围与通过标准

- 单元测试：导航权限映射、引导派生状态、术语映射、空间 scope URL 同步。
- 组件测试：四种文件页状态、设置菜单、会话抽屉、三点菜单、处理详情。
- 回归测试：上传、刷新、任务查看、进入问答、切换空间、退出登录。
- 端到端测试：空账号首次上传至成功提问；失败任务重试；管理员访问收纳后的管理入口。
- 无障碍测试：键盘顺序、focus-visible、ARIA 名称、触摸目标、对比度。
- 视觉测试：375、768、1024、1366 和 1440px，浅色与深色主题。

## 17. 后续测试文档要求

实现 Agent/LLM 必须为每个 TASK 编写完整测试用例并保存独立测试记录，包含测试目标、前置条件、数据、步骤、预期结果、实际结果和结论；未执行测试的任务只能标记为 `pending-verification`。

## 18. 风险、风险接受与观察项

- 导航收纳可能降低低频功能的短期可发现性：通过设置菜单搜索、旧 URL 和一次性更新提示缓解。
- 文件页承担双重职责可能再次变复杂：严格限制为一个主 CTA 和一个三步状态条。
- 多查询派生状态可能短暂不一致：使用保守状态与刷新入口。
- 用户已接受“不新增工作台，以文件页作为登录落点”的取舍。

发布后观察：上传转化率、索引完成后进入问答比例、首次成功提问耗时、导航返回次数和任务失败恢复率。

## 19. 官方资料来源与核验日期

本方案未引入新技术或依赖，不需要外部时效性技术选型。依据为 2026-08-04 的现有仓库代码、设计规范及已登录页面走查结果。

## 20. 审核与定稿记录

- 2026-08-04：用户批准方案范围、默认假设、风险处理方式和验收口径。
- 选定决策：不新增独立工作台；登录后继续进入文件页，由文件页承担“上传文件 → 查看处理状态 → 开始提问”的核心任务引导。
- 风险接受：低频功能收进设置可能降低首次可发现性；通过明确分组、权限化入口、旧 URL 兼容和发布提示缓解。
- 实施门槛：后续实现必须按 TASK-20260804-001 至 TASK-20260804-007 的依赖顺序推进；单项完成代码但未通过规定测试时，只能标记为待验证，不能标记为完成。
