# 运行方式与测试结果

## 安装依赖

建议在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[dev]"
```

## 运行 Level 1

运行 YAML 示例：

```powershell
python -m mini_agent_flow run examples/level1_manual_workflow.yaml
```

运行 JSON 示例：

```powershell
python -m mini_agent_flow run examples/level1_manual_workflow.json
```

安装后也可以使用脚本入口：

```powershell
mini-agent-flow run examples/level1_manual_workflow.yaml
```

## 运行 Level 2

Python 报错分析：

```powershell
python -m mini_agent_flow select --goal "帮我分析这个 Python traceback 报错"
```

研究总结：

```powershell
python -m mini_agent_flow select --goal "调研 Agent Workflow 的发展趋势并总结"
```

隐藏 Trace：

```powershell
python -m mini_agent_flow select --goal "调研 Agent Workflow 的发展趋势并总结" --no-trace
```

## 使用 DeepSeek

在 `.env.local` 中配置：

```text
DEEPSEEK_API_KEY=your-key
```

运行 Level 1：

```powershell
python -m mini_agent_flow run examples/level1_manual_workflow.yaml `
  --provider deepseek `
  --model deepseek-v4-flash
```

运行 Level 2：

```powershell
python -m mini_agent_flow select `
  --goal "分析这个 Python traceback 报错" `
  --provider deepseek
```

注意：

- 默认 Provider 是 Mock。
- 只有显式指定 `--provider deepseek` 才会产生真实 API 请求。
- `.env.local` 已加入 `.gitignore`。

## 真实 DeepSeek 测试结果

已完成一次真实 API 端到端测试：

```text
Goal：分析一个 Python TypeError 报错并给出简短修复建议
Provider：deepseek
Model：deepseek-v4-flash
选中模板：python_error_analyzer.yaml
真实 LLM 节点：analyze、suggest
执行节点：start -> analyze -> normalize -> suggest -> end
退出码：0
端到端墙钟时间：约 17.2 秒
```

测试中发现并修复：

- Windows GBK 标准输出无法渲染模型输出中的 emoji。
- CLI 已增加 UTF-8 标准流配置。

## 输出内容

CLI 通常展示：

- Workflow 名称。
- selected_workflow。
- selection_reason。
- final_output。
- executed_nodes。
- context。
- trace 摘要。

Trace 可用于定位：

- 哪个节点失败。
- 节点输入是什么。
- 节点输出是什么。
- 花费多久。
- 第几次 retry。
- Context 中新增或变化了哪些 key。
