# 文件系统与存储策略页面

## 目标与需求覆盖

完成 `/admin/fs` 与 `/admin/storage` 的完整前端结构，并将备份状态、历史和恢复校验并入存储策略页面。

## 前置依赖与输入

- 前置：TASK-20260913-001。
- 输入：现有 FileSystemPage、StoragePoliciesPage、旧 BackupStatusPage 历史实现和文件/备份领域文档。
- 下游测试：[[10-规划与实施/测试/TEST-20260913-001-管理后台前端页面验收要求]]。

## 修改范围与预期产物

1. 文件系统提供参数、全文搜索、文件图标、在线浏览应用四个完整标签。
2. 全文搜索具备模式、范围、关键词、结果摘要、证据详情和空/错误状态；本阶段不请求 Qdrant。
3. 文件图标与在线浏览应用具备筛选、列表、创建/编辑/启停和校验原型。
4. 存储策略提供概览、筛选、策略卡/表、详情、创建/编辑、启停和删除确认。
5. 备份标签提供统计、备份历史、详情和恢复校验结构；所有动作只更新内存状态。

## 明确不包含

- 真实搜索、上传参数生效、存储驱动、文件预览应用、备份创建、恢复或校验执行。
- 修改现有 AdminSearch、Backup API 或后端存储配置。

## 验收标准

- 两个页面所有标签均具备业务结构，不再使用锁定“敬请期待”内容。
- 默认空数据时筛选、列定义、操作入口和语义空状态仍可评审。
- 存储/备份/恢复等危险操作有影响说明、确认和非持久化提示。
- 测试 fixture 可展示搜索证据、策略详情、备份状态和异常状态。

## 测试、风险与回滚

- 测试：标签、搜索表单、结果展开、策略表单、备份详情、恢复确认、未知状态、长路径和空/错误数据。
- 风险：备份和恢复原型产生虚假安全感；不得显示“已完成真实备份/恢复”。
- 回滚：恢复当前 FileSystemPage/StoragePoliciesPage；真实 AdminSearch/Backup API 保留。
- 实现 Agent/LLM 必须生成完整测试用例和独立测试记录，并回写状态与证据。
