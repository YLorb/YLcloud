# 分片上传状态机

## 状态

~~~mermaid
stateDiagram-v2
  [*] --> UPLOADING: initfile
  UPLOADING --> UPLOADING: uploadChunk / status / resume
  UPLOADING --> MERGING: 取得合并租约且分片完整
  MERGING --> SUCCESS: 摘要校验与元数据事务成功
  MERGING --> UPLOADING: 可恢复失败或事务回滚
  UPLOADING --> EXPIRED: 超过保留期
  EXPIRED --> [*]: 清理临时分片
  SUCCESS --> [*]
~~~

代码中主要状态为 UPLOADING、MERGING 和成功终态。分片级执行权还通过 lease_until/upload_token 表达。

## 事件与守卫

| 事件 | 守卫条件 |
|---|---|
| 初始化 | 文件参数、摘要、大小、父目录和重名校验通过 |
| 接收分片 | uploadId 属于当前用户，索引合法，大小与 MD5 正确 |
| 开始合并 | 所有分片齐全且当前执行者获得租约 |
| 提交成功 | 合并对象 MD5/SHA1/SHA256 全部匹配，元数据事务成功 |
| 恢复 | 任务未完成、请求摘要与原任务一致、租约已释放或过期 |

## 并发语义

同一个 uploadId 的多个 merge 请求不能都创建 file_info/user_file。数据库 CAS 或租约只允许一个进入 MERGING；其余请求返回既有结果或 409。重复上传相同 chunk 应按摘要幂等，而不是重复计数。

## 故障恢复

- 缺片：拒绝合并，保持 UPLOADING，可继续上传。
- 摘要错误：删除最终对象全部版本，回到可恢复状态。
- MinIO compose 后数据库回滚：删除或复用已合并候选，不能留下伪成功元数据。
- 进程退出：已上传分片保留；租约过期后继续。
- 提交成功后清片失败：业务结果仍成功，清理作为可重试后置动作。

## 核心实现

MultifileService.initfile、uploadChunk、status、merge；ChunkUploadLeaseService；MultipartUploadCleanupService；MinioclientUtil。迁移 V3 增加摘要/uploadId，V19 增加租约和约束。
