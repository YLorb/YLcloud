# 文档解析与质量评估

## 产品目标

RAG 首先需要取得可信正文和结构。仅拿到文件名、MIME 或空字符串不能算解析成功。不同格式需要不同解析器，同时保留降级原因和质量信息。

## 解析抽象

DocumentParser 返回 ParsedDocument，包含正文、DocumentBlock、parser 类型/版本、metadata 和质量线索。HybridDocumentParser 按格式和结果选择：

- DocxStructuredParser：DOCX 结构化解析。
- TikaStructuredParser：通用 Office/文本解析。
- LayoutStructuredParser：版面服务。
- OcrStructuredParser：扫描件 OCR。
- VlmPageParser：复杂页面的可选视觉解析。
- DefaultDocumentTextExtractor：读取原文件并提供基础抽取。

ParserServiceClient 调用 document-parser-service 的 layout、ocr、page 等接口。解析结果写入 file_rag_parse_result，可按物理内容与 parser version 复用。

## 选择与降级

~~~mermaid
flowchart TD
  F[文件类型与内容] --> D{原生结构解析可用?}
  D -->|是| S[DOCX/Tika 结构结果]
  D -->|否或质量低| L[Layout]
  L --> Q{质量合格?}
  Q -->|否| O[OCR]
  O --> V{仍需视觉理解?}
  V -->|是且配置允许| P[VLM page]
  V -->|否| R[质量结果]
  S --> R
~~~

降级不是“任意异常后返回文件 metadata”。每一步需要记录 parser、version、状态和原因；最终正文为空或只含空白时索引必须失败。

## 质量评估

DocumentParseQualityAssessor 综合正文长度、字符分布、块数量、疑似乱码/空页和结构信息判断结果是否可用于切分。质量低可以触发其他解析策略或失败，但不能通过重复文件名制造正文。

## 核心代码与接口

- service.rag.parser 包中的 DocumentParser、HybridDocumentParser 与各实现。
- ParserServiceClient。
- FileRagParseResultMapper、file_rag_parse_result。
- 文档服务接口 /parse/layout、/parse/ocr、/parse/page。
- docs 中 parser/部署与 E2E 指南提供运行证据。

## 设计原因

解析器采用策略链，因为 PDF、DOCX、纯文本和扫描件不存在一个最优方案。缓存按 parser version 管理，升级解析算法后可判断是否需要重新解析。质量门槛放在切分前，减少“垃圾正文被精确 embedding”的无效成本。
