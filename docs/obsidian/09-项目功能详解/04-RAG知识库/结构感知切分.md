# 结构感知切分

## 产品目标

切分把长文档变成可 embedding、可检索、可引用的语义单元。切得太大导致主题混杂和上下文成本高，切得太小导致语义断裂；固定字符截断还会破坏标题、段落、表格和代码。

## 原理

StructuredChunker 优先使用 ParsedDocument 的 DocumentBlock、标题层级、页码和块类型组织 StructuredChunk。在结构边界内控制 chunkSize，并用 chunkOverlap 保留相邻上下文。无法取得结构时才使用 SpaceRagService.splitText 的受控文本降级。

每个 chunk 保存：

- 稳定顺序 chunkIndex；
- 正文 content；
- 文件 UUID/hash 与 parser 信息；
- 页码、标题、块类型等 metadata；
- 内容摘要或稳定签名所需信息。

## 流程

1. 过滤空块、纯空白和不应索引的噪声块。
2. 按标题/段落/页面形成语义段。
3. 段落过长时按 chunkSize 再分割。
4. 添加 overlap，但避免生成重复空内容。
5. 为每片生成顺序和来源 metadata。
6. 全局校验至少一个有效 chunk，拒绝 metadata fallback。

## 为什么需要 overlap

答案线索可能跨越切点。适度 overlap 能让相邻片都保留连接信息；但 overlap 必须小于 chunkSize，过大会放大存储、召回重复和 token 成本。

## 与检索的关系

切分质量决定召回上限。SpaceRagService.expandContextChunks 可在命中后按 chunkIndex 补邻接片，代码类问题还会扩大上下文。这样索引保持较细粒度，回答阶段再组合必要上下文。

## 核心代码与数据

- StructuredChunker、StructuredChunk、DocumentBlock、ParsedDocument。
- SpaceRagService.ensureFileChunks、splitText、expandContextChunks。
- file_rag_chunk、space_rag_chunk_ref。
- 配置：chunkSize、chunkOverlap。

## 成功条件

chunkCount=0 必须失败；每片 content 非空；缓存复用时文件 hash、parser version 和配置需匹配；最终 active ref 和 Qdrant point 与有效 chunk 数一致。
