# 多知识库问答与会话持久化

## 产品目标

用户可以从一个或多个已授权知识库提问，并保存会话历史，刷新、重新登录或跨设备后仍能继续。回答引用要明确标出来自哪个 Space。

## 多 Space 查询

KnowledgeRagController/KnowledgeRagQueryService 接收最多限定数量的 spaceIds，逐个验证当前用户是成员，再在授权范围执行检索。候选融合仍保留 spaceId/spaceName，最终 citations 能区分来源。

权限校验必须在检索前完成，不能先查询所有 Space 再过滤结果。一个未授权 Space 应使请求明确失败或按产品定义排除，不能静默泄露命中数量。

## 会话模型

knowledge_chat_session 保存 owner、标题、选择的知识库作用域和时间；knowledge_chat_message 保存 user/assistant 消息、答案、引用快照和顺序。V11 引入相关表。

KnowledgeChatSessionController 提供 sessions CRUD、scope 和 messages；KnowledgeChatSessionService 校验会话归属、Space 权限、消息顺序并调用知识问答。前端 AssistantSidebar、AssistantThread、AssistantComposer 和 AssistantChatView 负责列表、线程和输入。

~~~mermaid
sequenceDiagram
  participant U as 用户
  participant S as 会话服务
  participant R as 多Space RAG
  participant DB as 会话/消息表
  U->>S: 创建会话并选择 Spaces
  S->>S: 校验全部 Space 权限
  S->>DB: 保存 session/scope
  U->>S: 发送问题
  S->>DB: 保存 user message
  S->>R: 授权范围检索问答
  R-->>S: answer + citations
  S->>DB: 保存 assistant message
  S-->>U: 返回并刷新线程
~~~

## 一致性与失败

用户消息和助手消息应有明确顺序。模型调用失败时可以保留用户消息和失败状态，避免刷新后问题消失；重试应生成新执行记录或幂等关联，不能重复追加不明消息。

删除会话只影响会话历史，不删除 Space 文件、RAG 索引或画像。成员权限被撤销后，再次读取或继续会话必须重新校验 scope。
