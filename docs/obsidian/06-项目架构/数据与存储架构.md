# 数据与存储架构

## 数据所有权

MySQL 是业务真相源。MinIO 对象和 Qdrant 向量是由 MySQL 中的引用和任务驱动的外部资源。发生冲突时，不能用“Qdrant 有点”推断文档已完成，也不能用“MinIO 有对象”推断用户一定拥有逻辑文件。

## 文件数据模型

- file_info：物理内容元数据，记录 UUID、hash、MD5、大小、类型和存储信息。
- user_file：个人网盘逻辑节点，记录父目录、名称、所有者、目录/文件属性和删除状态。
- space_file：Space 内的逻辑节点和物理文件引用。
- file_version：Space 文件版本链，指向当时的物理内容。
- file_share：公开分享配置与分享码。

物理内容与逻辑节点分离，使秒传、复制、Space 导入和版本复用成为可能。清理必须等所有引用归零。

## RAG 数据模型

- file_rag_parse_result：按文件内容缓存解析结果、parser 和质量信息。
- file_rag_chunk：内容级 chunk，可跨 Space 复用。
- space_rag_document：某 Space 文件的索引状态和 vector_state。
- space_rag_chunk_ref：把内容 chunk 激活到特定 Space 文档，是检索 SQL 的授权和有效性门槛。
- space_rag_task：索引、重建、删除和修复任务。
- space_rag_query_log、space_rag_config_log：查询与配置审计。

Qdrant point payload 至少需要能够按 spaceId、documentId、file/chunk 身份过滤。点存在只是外部资源存在，只有 document=SUCCESS、vector_state=ACTIVE 且 active ref 有效时才可检索。

## 知识画像数据模型

- space_knowledge_pipeline_task/event：画像批次、阶段、计数和事件。
- space_knowledge_document_profile：当前画像资产。
- space_knowledge_question：文档问题资产。
- space_knowledge_profile_version：版本快照与恢复来源。
- space_knowledge_audit_log：分类、审核、恢复等操作审计。

来源快照保存 chunk ID、数量、字符数、parser version、稳定签名和 revision，用于判断正文是否需要重生成，还是只同步检索来源。

## 外部存储

MinIO 启用版本控制，删除时必须处理全部版本和删除标记。分片对象先保存到临时前缀，合并成功并提交元数据后再清理。

Qdrant collection 使用固定维度和距离度量。维度是系统级契约，模型、Spring 配置、collection 必须一致；否则应在启动或写入前失败，不能静默产生不可检索数据。

## Schema 演进

Flyway 从 V0_1 核心文件/用户表演进到 V22 RAG 跨存储一致性。迁移不仅增加字段，也承载默认值、唯一约束、历史数据清理和状态模型升级。任何生产升级必须同时验证空库、存量库、重复启动和回滚预案。
