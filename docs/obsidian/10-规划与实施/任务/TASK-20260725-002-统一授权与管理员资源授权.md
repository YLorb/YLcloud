# 统一授权与管理员资源授权
- 目标/需求：移除 ADMIN 全局数据豁免；统一用户、所有者、API Key 和系统任务主体；普通 ADMIN 仅在用户/TEAM OWNER 显式授权后读取私人资源。
- 依赖/输入：TASK-001；`AccessControlService/Mapper`、`AdminPermissionService`、拦截器。
- 修改范围/产物：`AccessSubject`、资源动作枚举、统一授权服务、管理员资源授权表/API；所有者越权路径与审计钩子。
- 不包含：API Key 创建、审计保留任务。
- 验收：Controller、Service、Tool 均不能绕过授权；授权撤销立即生效；普通 ADMIN 默认跨用户拒绝，所有者允许且留审计。
- 测试/通过：权限矩阵、跨用户/Space 负例、缓存撤销和并发授权测试通过。
- 风险/回滚：漏接入口导致越权；以入口清单和 deny-by-default 门禁验证，失败回滚本阶段代码与迁移。
- 回写：更新权限矩阵、入口清单和安全测试证据。
- 测试：[[10-规划与实施/测试/TEST-20260725-001-统一知识平台实施测试要求]]

## 实施回写

- 新增 `AccessSubject`、`AccessSubjectType`、`ResourceType`、`ResourceAction` 和 `AuthorizationBasis`，统一 Web 用户、API Key、系统任务及部署所有者判定。
- 新增 Flyway V33 `admin_resource_grant`，只允许 `USER_PRIVATE/SPACE` 的 `READ/DOWNLOAD` 显式授权；唯一约束收敛并发重复授权，状态撤销即时生效。
- 新增资源授权创建、查询、接收和撤销 API，以及跨用户个人文件的受控只读入口。
- 删除 `FileService` 中 `role=ADMIN` 任意文件查询、写入和删除豁免；分享等副作用操作不能复用 READ 授权。
- `SpacePermissionService` 接入统一授权，Controller、知识服务和 Workflow Tool 共享同一 Space 边界。
- 平台能力解析改为仅部署所有者豁免；其他主体按用户覆盖、用户组、默认拒绝计算。历史和新用户均自动归入默认用户组。
- 部署所有者越权读取/管理产生 `permission_audit_log` 审计钩子；审计写入异常不会改变其不可限制的访问语义。
- 权限矩阵与入口清单已回写到 [[09-项目功能详解/01-账号安全与配置/权限模型与Space角色]]。

## 验收结果

- 后端全量测试 173/173、授权专项测试 15/15 通过，后端生产包构建通过。
- Win10 Docker MySQL 空库成功应用 34 个迁移到 V33。
- 真实 API：普通 ADMIN 对用户文件/未加入 Space 默认 403；授权后均 200；撤销后下一请求恢复 403。
- 部署所有者跨用户访问返回 200，并写入 `DEPLOYMENT_OWNER_READ_USER` 审计事件。
- 两个并发相同授权请求均返回 200，数据库最终只有 1 条有效 READ 授权。
