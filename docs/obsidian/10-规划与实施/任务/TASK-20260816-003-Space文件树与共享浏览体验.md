# Space 文件树与共享浏览体验

## 目标与依赖

- 目标：把 Space 从全量文件平铺列表升级为可逐级浏览的文件树体验，并与个人网盘共享 File Explorer 的核心交互规范，同时保持 `user_file`、`space_file`、授权和知识生命周期相互独立。
- 覆盖：REQ-20260725-001 的 Space 文件树、默认知识化、双逻辑模型和权限扩展边界。
- 前置：ADR-20260817-001、TASK-20260817-001 至 TASK-20260817-004；后端授权、目录、搜索、Sandbox 导入和异步删除契约必须先完成。
- 下游测试：[[10-规划与实施/测试/TEST-20260816-003-Space文件树与共享浏览体验测试要求]]。

## 修改范围与预期产物

1. 建立共享 File Explorer 展示层，统一当前目录列表、目录进入、返回上级、面包屑、加载/空/错误状态、搜索入口和响应式布局。
2. 为 Personal 与 Space 分别提供数据适配器及 capability 上下文；共享组件不得直接假设 `user_file` 所有权或 `space_file` 成员角色。
3. Space URL 以 `space + tab + folder` 保存目录上下文，只加载当前层级；切换 Space 清空旧 folder，无效目录安全回根。
4. 使用受权 ancestors API 生成面包屑，使用整个 Space search API 定位结果目录；不在客户端全量过滤。
5. 创建、上传和导入携带当前 `parentId`；Personal 选择器支持文件/目录并让用户选择 ATOMIC/SKIP_FAILED。
6. 展示 Sandbox 导入批次进度、逐项失败、重复文件 409 定位；重复时不提供隐式移动。
7. capability 完全使用后端返回值；正式支持 OWNER/ADMIN/MEMBER/VIEWER，不在组件内复制角色判断。
8. 删除先展示影响统计和不可撤销警告；非空目录输入名称确认，提交后展示不可取消异步任务。
9. 保留知识状态、版本、贡献者、预览、下载等 Space 专属信息；MEMBER 版本操作遵守本人节点 capability。

## 明确不包含

- 合并 `user_file` 与 `space_file`，或引入 `Container/FileNode` 数据迁移。
- 文件/文件夹级 ACL、权限继承、拒绝规则或权限配置 UI。
- 改为手动选择是否知识化；Space 普通文件仍默认知识化。
- Office 协同编辑、虚拟目录、标签替代目录或跨 Space 移动。

## 验收标准

- 用户可在 Space 内逐级进入文件夹并通过面包屑、返回上级回到任意已授权祖先目录；刷新后可恢复或安全回退到有效目录。
- 在任意层级创建文件夹、上传及导入个人文件，节点都出现在当前目录，后端目录关系正确且无跨 Space 写入。
- Space 不再以全量平铺表格作为唯一主视图；大文件量场景只加载当前层级。
- Personal 与 Space 核心浏览体验一致，但 Space 所有请求继续执行角色授权，非成员和跨 Space 节点访问均被后端拒绝。
- Space 普通文件默认进入知识化流程，文件夹不进入；个人文件未导入 Space 前不因本功能自动知识化。
- 导入不复制物理对象，现有版本、知识状态、贡献者、预览和下载能力不回退。

## 测试范围、风险与回滚

- 必须：目录导航和路径单元测试、API 参数与权限回归、异常/边界、安全测试、Personal/Space 适配器组件测试。
- 条件启用：跨前后端集成测试、真实浏览器 E2E、大目录性能检查和目标浏览器兼容测试。
- 风险：共享组件泄漏 Personal 权限假设、切换 Space 后串用目录状态、上传落错目录、全量树导致性能退化、知识化触发回归。
- 回滚：发布前保留可回滚构建；切换后不保留旧平铺组件双运行。应用回滚不恢复已隔离删除节点、不绕过 Sandbox。
- 实现 Agent/LLM 必须生成完整测试用例，执行适用测试，创建独立测试记录，并回写实现、验证和剩余风险；未完成必选测试只能进入 `pending-verification`。
