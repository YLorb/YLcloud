# Compose 配置、健康检查与可观测性
- 目标：将 Workflow 加入本地/Hub Compose，建立内部网络、Secret、健康、资源限制、关联 ID、指标和日志。
- 依赖：TASK-002/003/004/005/010。
- 产物：以 Ubuntu 22.04、4 核/16GB、无 GPU、Compose `mysql:8.3` 为基线的 services/env examples/healthcheck，`workflow-service:8003` 配置，固定 `http://ylcloud-app:8080/internal/v1/workflow-callbacks` 回调配置，model-service 分能力 readiness，trace propagation，阶段耗时和告警指标；本地采集并发 Run、P50/P95、最长运行时间、模型调用量和成本基线。
- 不包含：Kubernetes 和多区域部署。
- 验收：本地 Compose 全链路通过；冷启动/重启/依赖不可用有明确状态；Workflow 通过 Compose 服务名回调 Java，不使用容器自身 localhost；Plan/Rerank/Generate 任一必需能力未就绪时 readiness 正确失败或阻止相应流量；无循环 depends_on；生产配置模板无宿主端口；日志无正文和 Secret。测试结论明确记录无独立测试/灰度环境、未执行生产部署，不把本地结果表述为生产验证。
- 风险/回滚：配置名漂移；启动契约校验，删除 Workflow service/feature flag 即回滚。
- 回写：镜像 tag、Compose smoke、资源曲线、开放端口和告警阈值。
