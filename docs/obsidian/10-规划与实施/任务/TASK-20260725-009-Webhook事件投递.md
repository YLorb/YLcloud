# Webhook 事件投递
- 目标/需求：提供文件、知识、Agent 和 Space 事件订阅，至少一次投递、签名、重试、事件幂等及可选正文。
- 依赖/输入：TASK-007/008；业务 Outbox、站点设置。
- 修改范围/产物：订阅/事件/Delivery 表、签名 Secret、投递 Worker、退避与死信、SSRF 策略和管理 UI 契约。
- 不包含：跨资源全局有序和恰好一次。
- 验收：唯一 `eventId`、版本、时间戳齐全；正文受 Scope 控制；每次解析/重定向检查目标 IP；内网仅所有者显式开放。
- 测试/通过：重复、乱序、超时、签名轮换、DNS rebinding、重定向和跨用户泄漏测试通过。
- 风险/回滚：SSRF/数据外泄；默认禁用内网与正文最小化；紧急停用投递 Worker。
- 回写：已交付 Subscription/Event/Delivery 持久状态机、同事务事件扇出、Agent/Workflow 终态对账、租约与至少一次投递、5 秒起步且最长 1 小时的指数退避、最大次数死信、HMAC-SHA256 签名与 Secret 轮换窗口、API Key 实时 Scope 正文裁剪、每跳 DNS/重定向 SSRF 校验、校验 IP 固定连接和部署所有者私网策略。事件目录覆盖文件、知识、Agent 和 Space 成员变更；管理端 TypeScript API/类型与 `docs/webhook-v1.md` 已发布。Win10 Docker/MySQL/真实 HTTP 验证首次 500 后同 eventId 重试为 204，当前与旧签名均有效，数据库无明文 Secret；当前构建另以固定 IP 客户端完成单次 204 烟测并清理订阅/Key/设置。10 事件基线吞吐 3.21 次/秒，P50 986.838 ms、P95 1459.94 ms。
