# 平台预置工具 Sandbox

## 背景与目标

YLcloud 需要为文件处理、第三方本地程序和高资源消耗工具建立独立执行边界，避免工具读取宿主机数据、窃取凭据或耗尽应用节点资源。Sandbox 只执行平台审核并预置的工具，不接收用户代码、任意 Shell、动态依赖或自定义镜像。

下游决策见 [[10-规划与实施/ADR-20260813-001-独立Sandbox服务与一次性容器架构]]。

## 范围

1. 新建独立 `sandbox-service`；生产 Runner 部署在独立 Linux 节点。
2. 每次 Tool Invocation 使用固定镜像、固定入口、结构化 JSON 参数和一次性容器。
3. 输入只读，输出由控制面校验；Sandbox 不直接访问 MySQL、RabbitMQ、MinIO 或业务 API。
4. 默认断网；首版不开放联网工具。
5. Workflow 新增 `execution_mode: sandbox`，保留 `inline` 与 `isolated_process` 语义。
6. Sandbox 调用作为 Tool Node Trace 的子 Span 元数据保存，不建设平行审计库，生命周期跟随父 Trace。

## 非目标

- 任意 Python/Shell、用户镜像、运行时安装包、GUI 或常驻服务。
- 用 Sandbox 替代 Tool Gateway 的身份、资源权限和高风险授权。
- 首版计费。
- Sandbox 故障时回退到应用宿主机执行。

## 验收标准

- 未注册工具、未知版本、非法参数、超限参数均在创建容器前拒绝。
- 容器使用非 root、只读根、全部 capability 移除、`no-new-privileges`、默认 seccomp、无网络、PID/CPU/内存/磁盘/超时约束。
- Sandbox 无 Docker Socket、平台密钥或业务网络访问能力。
- Workflow 能调用 Sandbox Tool，并把 invocation/span、安全策略、资源和终态写入节点 Trace。
- 取消/超时终止容器；重复 idempotency key 不重复执行。
- 用户只能查询与其身份及父 Trace 关联的历史。

## 约束与默认值

- 默认 1 CPU、512 MiB、64 PID、1 GiB 临时空间、60 秒超时，最大 600 秒。
- 单输入 200 MiB、输入合计 500 MiB、输出合计 500 MiB、最多 1000 文件；压缩展开倍率 20、嵌套 3 层。
- 生产只支持 Linux；Windows Docker Desktop 仅作开发验证。
