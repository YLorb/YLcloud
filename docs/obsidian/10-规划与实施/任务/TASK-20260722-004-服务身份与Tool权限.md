# 服务身份与 Tool 权限
- 目标：建立 Java ↔ Workflow ↔ Model/Tool 的服务身份、audience、短期 Token、Tool scope 和审计边界。
- 依赖：TASK-001/002。
- 产物：Java→Workflow、Workflow→Java Tool、Workflow→model-service 及 Workflow→Java callback 的独立 audience；首版 HS256 JWT issuer/verifier、active/previous secret 受限轮换重叠期、scope 检查、服务时钟偏差策略、脱敏日志和诊断审计；JWKS 作为后续迁移项。
- 不包含：终端用户 OAuth 和前端 Token 传递。
- 验收：伪造/过期/错 audience/超 scope Token 全部拒绝；Token 绑定 user/session/message/run；回调 Token 与普通调用 Token 不可混用；model-service 拒绝未认证调用；日志无密钥和记忆正文。
- 风险/回滚：时钟漂移、共享密钥泄漏或轮换中断；Secret 由 Compose/部署环境注入，Java 只消费不生成宿主 Secret；允许受限 active/previous secret 重叠期，feature flag 回退到 Workflow 禁用。
- 回写：Claims 契约、密钥轮换步骤和安全负例结果。
- 测试：[[10-规划与实施/测试/TEST-20260722-001-Workflow服务集成测试要求]]

## 实施回写

- Claims 权威契约：`schemas/service-jwt-claims.schema.json`；固定四个 audience：`ylcloud-workflow`、`ylcloud-tool-gateway`、`ylcloud-model-service`、`ylcloud-workflow-callback`。
- 首版算法：仅允许 `HS256`；必须包含 `iss/sub/aud/iat/nbf/exp/jti/scope`，最长 TTL 300 秒，允许时钟偏差上限 60 秒，Token 长度上限 4096 bytes。
- 绑定：Run 创建绑定 `userId/sessionId/assistantMessageId`；已创建 Run 的读/取消/重试绑定 `runId`；Tool 约束 user/session/message/run/execution/node/invocation；model 至少绑定 run；callback 绑定 user/session/message/run/execution。
- Java：新增独立 Service JWT issuer/verifier、四 audience 常量、scope/绑定校验和 active/previous 验证；原 Java model-service 调用按端点签发最小 scope Token。
- Workflow：所有 `/internal/v1/workflow-runs` 端点 fail-closed 鉴权；缺 Secret 时 `/ready` 不就绪且内部操作返回 503；提供 Workflow 出站 Tool/model/callback issuer。
- model-service：`/embed`、`/rerank`、`/chat`、`/generate` 分别要求精确 scope，缺凭证/伪造/错 audience/过期返回 401，超 scope 返回 403；health/ready 仅供探针且不接收模型输入。
- Secret：用户 JWT 与 Service JWT 分离；active 由只读部署 Secret 文件注入。previous 必须同时配置绝对截止时间，且重叠窗口不得超过最大 TTL+时钟偏差（当前 360 秒）；截止后即使 Secret 残留也拒绝旧签名。步骤见 Workflow `docs/SERVICE_JWT.md`。
- JWKS/OAuth：仍按已确认范围后置，不在本任务实现。
- 测试证据：[[10-规划与实施/测试/TEST-20260722-005-TASK-004-服务身份与Scope测试记录]]。
