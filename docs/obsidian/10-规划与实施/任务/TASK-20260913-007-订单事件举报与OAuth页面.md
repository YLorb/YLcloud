# 订单、事件、举报与 OAuth 页面

## 目标与需求覆盖

替换 `/admin/orders`、`/admin/events`、`/admin/reports`、`/admin/oauth` 的通用占位页，完成四个独立领域的前端结构；安全审计归入事件页面。

## 前置依赖与输入

- 前置：TASK-20260913-001。
- 输入：旧 SecurityAuditPage、当前 SecurityAudit API 类型、订单/事件/举报/OAuth 的页面范围决策。
- 下游测试：[[10-规划与实施/测试/TEST-20260913-001-管理后台前端页面验收要求]]。

## 修改范围与预期产物

1. 订单页：状态/类型/用户/时间筛选、指标、金额格式、列表、详情和状态操作原型。
2. 事件页：系统事件与安全审计标签、级别/类型/主体/时间筛选、详情、结构化载荷和审计留存设置。
3. 举报页：状态/类型/优先级/责任人筛选、证据摘要、详情、分派、驳回和处置确认。
4. OAuth 页：应用列表、状态/所有者筛选、创建/编辑、Scope、回调地址、启停、删除和演示 Secret 一次性展示。
5. 所有未知枚举、空数据、长载荷、无证据和命令失败具备安全退化。

## 明确不包含

- 支付、退款、审计写入/清理、举报工作流、外部证据访问、OAuth 客户端注册或 Secret 生成后端。
- 将页面字段认定为最终公共 API 或数据库模型。

## 验收标准

- 四个路由均使用专属页面，不再引用 PlaceholderPage。
- 事件页明确区分系统事件和安全审计；审计留存调整只更新内存。
- 金额使用整数最小货币单位格式化；事件内容通过 React 转义；OAuth 不展示真实 Secret。
- 所有危险操作有确认和演示提示，失败不修改页面数据。

## 测试、风险与回滚

- 测试：四页空/有数据、筛选、详情、未知枚举、金额、载荷转义、举报处置、Scope/URL 校验、Secret 单次展示和危险确认。
- 风险：缺少最终后端契约；领域模型必须标记为 prototype，并集中在 adminModels 中方便替换。
- 回滚：四路由恢复占位页；旧 SecurityAuditPage/API 保留。
- 实现 Agent/LLM 必须生成完整测试用例和独立测试记录，并回写状态与证据。
