# 知识画像定位、开关与任务编排

## 产品定位

知识画像从已完成 RAG 索引的文档中提取摘要、分类、标签、关键词、问题和质量信息，用于知识运营与增强检索。它不是文件加入知识库的必经步骤，也不能替代解析、切分、embedding 和向量索引。

基础 RAG 成功后即可以问答；画像关闭或失败只影响增强能力，不改变 RAG_READY。

## 开关设计

space_rag_config.knowledge_profile_enabled 由 V21 增加，数据库默认 true，存量知识库迁移后统一开启。GET/PUT RAG config 返回和保存该字段，只有 OWNER/ADMIN 可修改，并记录配置审计。

RAG 完成时 SpaceRagService.submitKnowledgeProfileTask/submitKnowledgeProfileSpaceTask 读取数据库最新值：

- true：创建 PROFILE_DOCUMENT 或单一 PROFILE_SPACE 批次。
- false：不调用模型、不生成画像、不创建画像版本/事件，持久化 SKIPPED/PROFILE_DISABLED。

关闭不删除历史画像；重新开启只影响新的 RAG 完成或显式重建。

## 编排流程

~~~mermaid
flowchart TD
  R[RAG document SUCCESS/ACTIVE] --> F{读取最新画像开关}
  F -->|关闭| S[SKIPPED / PROFILE_DISABLED]
  F -->|开启| T[创建 PENDING 画像任务]
  T --> C[afterCommit 异步调度]
  C --> X[CAS PENDING→RUNNING]
  X --> E[生成、校验、写资产]
  E --> O[批次 total/success/failed]
  O --> N[前端轮询恢复通知]
~~~

## 批次语义

空间重建只创建一个 PROFILE_SPACE 批次，避免每文档任务和空间批次重复通知。活动任务由唯一约束保护。零符合条件文档是 SKIPPED/NO_ELIGIBLE_DOCUMENTS；全部失败是 FAILED；完成通知显示本批“成功 X、失败 Y”，不能读取历史累计数。

## 核心代码

- SpaceRagService：RAG 后检查开关和提交任务。
- KnowledgePipelineService：submitDocument、submitSpace、executeDocumentTask、executeSpaceTask。
- KnowledgePipelineExecutorService：异步入口。
- SpaceKnowledgePipelineTaskMapper：CAS、批次计数和唯一任务。
- KnowledgeOpsView/KnowledgeBaseView：任务分区、开关和通知。

## 设计原因

开关按 Space 保存，符合团队知识库自治；运行时读取最新值，避免任务创建早于用户关闭动作。跳过也持久化终态，刷新页面后用户仍能知道“为什么没执行”，而不是看到任务消失或 SUCCESS/0/0。
