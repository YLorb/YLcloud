# 任务持久检查点与人工续跑

- 目标：为可安全暂停的统一任务持久化流程步骤与幂等状态，节点恢复后允许用户手动续跑。
- 前置与输入：TASK-20260913-017；现有 `TaskExecutionContext.checkpoint()`、任务租约/attempt、各任务处理器和用户确认的“记录后中断”。
- 产物：检查点表/版本、暂停请求/已暂停状态、处理器 resumable 能力声明、人工恢复 API、前端操作可用性与失败原因。现有 `checkpoint()` 的取消/心跳职责保留，持久步骤另建协议。
- 不包含：无检查点任务的强杀/伪续跑、真实跨机执行调度；节点监控仍可 Mock。
- 验收：安全边界持久化后才释放租约；恢复从已提交步骤启动且不重复副作用；同一任务并发恢复只成功一次；不支持恢复者返回冲突并保留可诊断状态。
- 测试：按处理器盘点可恢复性、崩溃前后重入、重复恢复、旧任务无 checkpoint、节点离线、资源版本变化、权限与审计、跨模块集成；通过才完成。
- 风险与回滚：部分外部副作用无法原子撤销；每处理器建立幂等键/补偿证据，先在测试库验证；可关闭新暂停入口，不能删已写 checkpoint。
- 回写：实现 Agent 生成完整用例和独立记录，列明逐任务类型能力矩阵并回写状态；下游 [[10-规划与实施/测试/TEST-20260913-002-管理后台真实API与节点绑定测试要求]]。
