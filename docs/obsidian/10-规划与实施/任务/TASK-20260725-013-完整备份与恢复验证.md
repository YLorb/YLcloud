# 完整备份与恢复验证
- 目标/需求：每天04:00 UTC+8在线备份 MySQL、MinIO、Qdrant 和必要配置；隔离完整恢复通过后才发布并轮换。
- 依赖/输入：TASK-012/016；Compose、Secret 文件机制、各存储官方备份能力。
- 修改范围/产物：备份/恢复脚本、临时目录、manifest/hash、状态记录、隔离 Compose 验证、保留策略；备份外文件型加密密钥；RabbitMQ 拓扑/配置/Secret 清单和由 MySQL 任务事实/Outbox 恢复派发的验证。
- 不包含：HTTPS、跨区域容灾、多节点 HA。
- 验收：不中断业务；失败不删除上一份 READY；默认保留1份；缺密钥不能恢复；归档不含明文 Secret；无需把 RabbitMQ 消息卷当作任务唯一恢复源。
- 测试/通过：真实全量恢复、损坏/空间不足/进程终止/密钥缺失、轮换和业务抽样一致性通过。
- 风险/回滚：误把未验证备份视为成功；状态机与原子发布，上一份 READY 始终保留。
- 回写：记录耗时、容量、manifest、恢复抽样和演练证据。
- 测试：[[10-规划与实施/测试/TEST-20260725-001-统一知识平台实施测试要求]]

## 实施内容

### 数据库迁移 (V50)
- 新建 `backup_run` 表：备份运行状态跟踪
  - 状态机：PENDING → RUNNING → VERIFYING → READY / FAILED / EXPIRED
  - 记录 manifest、archive path、hash、size、encryption key ID
- 新建 `restore_verification` 表：恢复验证记录
  - 记录各组件恢复状态和业务抽样检查
- 新建 `backup_retention_config` 表：保留策略配置
  - 默认保留1份 READY 备份

### 备份脚本 (scripts/backup.sh)
- 前置检查：docker、mysqldump、openssl、磁盘空间（10GB）
- 加密密钥管理：自动生成 AES-256 密钥，存储在备份目录外
- MySQL 备份：mysqldump --single-transaction --routines --triggers --events
- MinIO 备份：docker cp 或 mc mirror
- Qdrant 备份：触发 snapshot API + docker cp
- 配置备份：compose、env、secrets、scripts
- Manifest 生成：JSON 格式，包含各组件 hash 和 size
- 加密归档：tar.gz + AES-256-CBC 加密
- 完整性验证：hash 校验 + 解密测试
- 轮换策略：保留指定数量的 READY 备份

### 恢复脚本 (scripts/restore.sh)
- 参数支持：--verify-only、--skip-*、--dry-run
- 完整性验证：hash 校验 + 解密测试
- MySQL 恢复：停止应用 → 导入 dump
- MinIO 恢复：停止服务 → docker cp → 重启
- Qdrant 恢复：停止服务 → docker cp → 重启
- 配置恢复：secrets 目录恢复
- 业务抽样验证：启动应用 → 健康检查 → API 验证

### 后端实现
- `BackupRun` / `RestoreVerification` 实体
- `BackupMapper`：备份和恢复验证数据访问
- `BackupService`：备份状态管理和轮换
- `BackupController`：管理 API (`/api/admin/backup/*`)

### 安全特性
- 加密密钥存储在备份归档外
- 归档不含明文 Secret（加密存储）
- 缺密钥无法恢复
- 失败不删除上一份 READY 备份

### 测试结果
- 后端全量 283 项测试通过
- 编译成功，无错误

## 已知限制
- 备份脚本需要在 Linux 环境执行（依赖 mysqldump、openssl）
- 隔离恢复验证需要手动执行 restore.sh --verify-only
- 未实现自动定时备份（需配置 cron 或 systemd timer）
