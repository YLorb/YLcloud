# 安全、配置与部署架构

## 身份与授权

登录成功后签发 JWT，JwtTokenInterceptor 在受保护路径解析用户身份。业务层不能只相信客户端提交的 userId 或 spaceId；SpacePermissionService 按成员关系与 OWNER/ADMIN/MEMBER 角色执行资源级校验。

公开分享是例外入口：访问能力由高熵 shareCode、有效状态和资源存在性共同决定，不等同于登录权限。

## 配置分层

| 配置类型 | 位置 | 示例 |
|---|---|---|
| 业务可调配置 | MySQL + 管理接口 | topK、temperature、画像开关 |
| 部署配置 | application/env/Compose | endpoint、并发、超时、端口 |
| 敏感配置 | Docker Secret 文件 | JWT secret、LLM API key |
| 外部资源结构 | 初始化器/迁移 | MinIO bucket、Qdrant collection |

业务配置需要变更日志；Secret 不应进入数据库快照、日志、Git 或前端响应。SecretFileEnvironmentPostProcessor 把 FILE 引用转换为应用所需属性。

## 部署拓扑

默认 Compose 启动七个服务：

1. MySQL
2. MinIO
3. Qdrant
4. model-service
5. document-parser-service
6. Spring Boot app
7. Nginx/React frontend

基础依赖应先通过健康检查，再启动依赖它的业务服务。宿主机 MySQL、MinIO、Qdrant、模型、解析和后端端口默认绑定 127.0.0.1，前端作为公开入口绑定 0.0.0.0。

## 启动过程

~~~mermaid
flowchart TD
  V[加载环境和 Secret] --> D[启动数据服务]
  D --> H[健康检查]
  H --> F[Flyway 迁移]
  F --> I[Bucket/Collection 初始化]
  I --> A[应用启动]
  A --> R[恢复超时任务与一致性对账]
  R --> W[前端对外服务]
~~~

## 安全重点

- 密码只保存 BCrypt hash，注册日志不得包含 DTO 全量内容。
- 上传文件名、路径、MIME 和大小均需服务端验证。
- 下载、预览、版本和 RAG 引用链接每次都要重新验证访问权。
- 管理 API 使用平台 ADMIN，Space 配置使用 OWNER/ADMIN，不能混淆。
- 外部模型响应和解析内容不得拼接为未经限制的 SQL、路径或对象键。
- 生产需要 HTTPS、Secret 轮换、最小网络暴露、备份和日志脱敏。

## 当前部署风险

Qdrant client/server 版本与 Flyway/MySQL 支持矩阵仍需收口；数据库配置到运行时的热加载语义也未完全统一。升级必须先备份数据卷，并在验收环境验证迁移路径。
