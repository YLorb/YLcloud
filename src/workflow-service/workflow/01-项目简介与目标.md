# 项目简介与目标

## 项目简介

Mini AI Workflow Builder 是一个小型 Agent 工作流平台，目标不是一开始复制 Claude Code 或 LangGraph，而是从更底层、更可控的方式理解 Agent 产品的核心结构。

项目把一个 Agent 系统拆成：

- Workflow 配置。
- Loader 与 Validator。
- Context 共享状态。
- Variable Resolver。
- LLM 节点。
- Tool 节点。
- Condition 分支。
- Retry。
- Trace。
- Planner / Selector。

它的核心学习价值在于：很多 Agent 产品，本质上都是 Workflow + Tool + Context + LLM Planning 的组合。

## 项目目标

短期目标是在 2 到 3 天内完成一个与 Agent 强相关、可运行、可测试、可讲解的项目。

长期目标是逐步演进成一个小型 Agent Workflow 平台：

```text
Level 1：执行人工定义的 Workflow
Level 2：AI / 规则从模板库选择 Workflow
Level 3：AI 根据 Goal 生成 Workflow
```

## 为什么先做 Workflow Engine

项目没有直接做完全自主 Agent，而是先做确定性 Workflow Engine。

原因：

- 执行路径可控，适合学习和调试。
- 每个节点输入、输出和状态可以被 Trace 记录。
- Tool 调用可以先被白名单和 Validator 约束。
- 后续接入 AI Planner 时，Planner 只负责选择或生成流程，Executor 仍然保持稳定。

也就是说，本项目先把 “能稳定执行” 做扎实，再逐步加入 “能智能规划”。

## 三个 Level 的定位

### Level 1：执行人工定义的 Workflow

用户手写 JSON / YAML Workflow，Engine 负责加载、校验、执行和记录 Trace。

它证明项目已经具备一个基础 Workflow Engine。

### Level 2：从模板库选择 Workflow

用户只输入 Goal，系统从模板库选择最合适的 Workflow，然后填充输入并执行。

它证明项目具备 Planner-Executor 分层能力。

### Level 3：根据 Goal 生成 Workflow

用户只输入 Goal，AI 生成 Workflow，系统校验后执行。

这是更接近完整 Agent Planning 的阶段，但必须建立在 Level 1 和 Level 2 稳定基础上。

## 当前状态

当前项目已经可以写入简历，但表述要准确：

- 可以说实现了一个 Python Agent Workflow Engine。
- 可以说支持人工 Workflow 执行和规则模板选择。
- 可以说接入了 DeepSeek OpenAI 兼容 API。
- 不应该说已经实现通用 LangGraph 替代品。
- 不应该说已经支持任意 DAG、完整 Loop 或开放领域自动生成 Workflow。
