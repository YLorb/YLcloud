## 安全负例

- 伪造签名、过期、未来生效、超过 300 秒 TTL、错 issuer/subject/audience、缺 jti/nbf、非法绑定全部拒绝。
- callback Token 不能调用 Tool/model/Workflow audience；普通 Run Token 不能作为 callback Token。
- scope 采用端点最小权限，读、创建、取消、重试及四个模型能力互不隐式包含。
- previous Secret 没有明确截止时间时配置失败；截止时间超过 360 秒窗口时配置失败；截止后旧 Token 拒绝。
- 缺 active Secret 时内部业务端点 fail-closed，不降级为匿名；健康探针不传递 question/context/model input。
- 错误只暴露固定分类，不包含原 Token、签名差异、Secret、用户正文或记忆正文。

## 正确性审查

- Java JJWT 与 Python 标准库实现使用同一 seconds-based Claims 语义、固定 audience 名称和资源字段；权威 JSON Schema 覆盖条件必填字段。
- Java 旧 RAG model client 的四个端点均签发独立 `model.*` scope，避免 model-service 加固后破坏原功能。
- Workflow Run API 在业务服务前完成验签、scope 和资源绑定校验；无效请求不会进入 MySQL Store。
- 轮换同时验证 active/previous，但 previous 只在明确、短时截止窗口内有效。

## 安全审查

- 仅接受 header `alg=HS256` 且签名常量时间比较；Token 限长，JSON/时间/绑定类型严格校验。
- Service JWT Secret 与用户登录 JWT Secret 分离，通过 `.secrets/service_jwt_active_secret` 只读挂载；示例文件不是真实 Secret。
- 不记录或回显底层 JWT/验签异常；没有新增用户 Token 透传、任意 audience 或匿名 fallback。
